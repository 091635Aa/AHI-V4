## 0. 一句话主张 + 三处口径修正

### 0.1 主张（可证伪）

**C13 的可执行口径 = 三级指纹（L1 决策／L2 格上状态／L3 原始位型）× 独立进程 ×4 配置 × 检测器阳性对照（必须能失败）× 状态完整性（逐数组扰动 + 断点续跑）× 外部工具三分类（禁／可重放／实时单列）；通过线只取 L1∧L2，L3 仅作同机回归守卫，跨硬件本轮不可主张。**

**可证伪点**：若 4 配置下 L1 或 L2 任一不同 ⇒ C13 不成立；若阳性对照注入后 L2 仍同 ⇒ 检测器失效、全部 C13 结论作废（U0）；若某状态数组的 1 格步扰动不改变 L2 ⇒ 该数组不在指纹里、状态清单不完整。

**R1 §8.2 的现状**（[实测]，`蓝队/R1_立场.md:507-513`）：3 配置（HASHSEED 0/12345 × OMP 1/4）决策与全状态指纹全同——**这只证明"该路径两趟一致"，不证明"检测器有灵敏度"**（R1 自己已标注该缺口，`:513`）。本件扩到 **4 配置并补齐阳性对照**（§5）。

### 0.2 三处必须修正的口径（本件核心增量；均有本轮实测支撑）

| # | 原口径（R1 §8.4 / 队内 `R2_判据规格.md` T1·MF-DT-01·DT1） | 本件实测发现 | 修正后口径 |
|---|---|---|---|
| **修正 A** | "注入中间态 `np.float32` ⇒ 两趟全状态指纹**必须不同**"（`R2_判据规格.md` §1.4 T1、§3.6 MF-DT-01） | 对**已量化到 2^-20 格**的状态做 float32 存储中转是**无损**的：V4 核 20,993 个状态元素、千层 823,624 个元素**全部**满足 `x·2^20∈ℤ` 且 `max|x|≤15`，而 `15·2^20=15,728,640<2^24` ⇒ float32 mantissa 可精确表示。**实测：float32 存储注入后三枚指纹全同**（不是违规，是注入无效） | 注入必须落在**量化前计算路径**：把模块级 `_归` 换成"先 float32 计算、再量化"的测试替身（仅内存 monkeypatch，不改文件）。**本件实测：决策指纹同、原始/格上指纹不同**（§5.2）。故 MF-DT-01 的"必须不同"**只能判在状态指纹（L2/L3）上，不能判在决策指纹上** |
| **修正 B** | C13 通过线＝"全状态 **float64 `tobytes()`** sha256 4/4 全同"（`R2_判据规格.md` §1.4 T1） | 原始位型指纹对**亚格噪声**过敏、对**功能**无判别力：1 ULP 注入 ⇒ 原始指纹不同、格上指纹同（§5.2）；反之跨硬件 ULP 漂移会改 L3 而 L2/功能可能不变。若用 L3 当通过线，跨机必然"假失败"，同机也无法区分"功能变了"与"噪声被量化吸收" | 通过线＝**L1（决策 bytes）∧ L2（格上 int64 状态）**；L3 只作**同机同构建**的回归守卫（同机 L3 不同 ⇒ 红，查浮点路径；跨机 L3 不同不判失败） |
| **修正 C** | "dict 遍历顺序依赖 ⇒ 两趟必须不同"（`R2_判据规格.md` §1.4 T1、§3.6 MF-DT-03）——三项阳性对照之一 | 当前链路**没有**顺序依赖：4 配置（含 `PYTHONHASHSEED` 0/12345）全同（§5.2）。它不是"检测器灵敏度"对照，而是**读序审计臂**；强行要求"必须不同"会把合规实现误判 INVALID | 拆成两件：①**读序审计**（静态：所有集合/字典遍历转 `sorted`；动态：HASHSEED 0 vs 12345 必须**同**，不同才追；同＝合规记录）；②**检测器灵敏度**由「换种子」「1 格步注入」「量化前 float32 计算注入」三件证明（§5.2 已实测） |

### 1.2 三级指纹与规范序列化（口径写死）

```
# L2/L3 统一规范序列化（伪代码；观测口径，不是可执行件）
H = sha256()
for name in sorted(状态清单):                 # 名字排序 ⇒ 与 dict 插入序无关
    a = np.ascontiguousarray(state[name])      # 统一 C 序（== 内存位序）
    H.update(name.utf8 + "|" + a.dtype.str + "|" + shape_csv + "|" + a.tobytes())
# L2：先断言 a*2^20 == rint(a*2^20)（违例 ⇒ 该趟 INVALID），再以 int64 序列化
# L3：直接 float64 tobytes
# L1：hash(训选, 训奖, 测选, 测奖, 迁移选/奖, Acc 标量 repr, 版本号)
```

**状态清单（本件实测确认的 V4 路径充分统计量；20,993 元素）**：`P`（256×3）、`读出`（2×256）、`感W`、`自我W`、`自我态`、`最近门`、`_最近B`、`_o`（各 256）、`自我标量`（1）、`W表` 8 个算子数组（绑/解绑/门/叠/归/迭代/符 各 256；读 64×256）。**千层**：递归展开 `vars(核)`（含 `容器`/`记忆` 嵌套）⇒ 130 个数组、823,624 元素（本件实测）。

- **必须入指纹**：一切**可变态＋参数**；`规则随机` 模式的 `_rng.bit_generator.state`（否则漏随机源）；计数器（轮号/档/重放计数）；决策序列。
- **可排除（须显式声明并过 §2-P6 断点续跑）**：日志、墙钟/诊断字段、对象地址、文件 mtime、JSON 键序、缓存热态。**排除规则不是"省事"，而是由 P6 证明"排除后仍能逐位续跑"**。
- **禁止**：把"模型指纹"写成只 hash `选/奖`（现 `:72-74` 即此，属盲区：两趟决策同 ≠ 两趟状态同，R1 A-自3）。

### 1.3 四件套

- **主张**：按 §1.1 六项写死后，C13 在**同机跨进程**范围可判且可失败；现有"同进程两趟 + 决策指纹"**不构成** C13 证据。
- **证据**：4 配置 4/4 全同 [实测]；格断言 0 违例 [实测]；现有判据两趟同进程 `:312-319`、指纹只 hash 决策 `:72-74` [实测/静态]。
- **反证**：任一配置 L1/L2 不同 ⇒ 失败；格断言出现违例 ⇒ 数值策略被破坏（该趟 INVALID）；阳性对照注入后 L2 不变 ⇒ 检测器失效（U0）。
- **代价**：4 配置≈4×单趟（V4 800 拍 0.11–0.14 s/趟 [实测] ⇒ 含进程启动约 1.5–2 s [推算]；千层 30 拍含构造 1.2–2.2 s/趟 [实测] ⇒ 4 配置约 6–9 s [推算]）；哈希成本：千层 6.56 MB→8.1–13.0 ms/趟 [实测]，V4 0.16 MB→**未单独测**（<1 ms 量级，不得写成实测）。

## 2. 执行协议 P0–P7（可复跑；每步含判据）

| 步 | 动作 | 通过线 / 失败条件 |
|---|---|---|

| **P1 预注册** | 跑前写死并记 sha256：臂清单、阈值、种子族、状态清单、注入清单、环境快照 | 跑后改动任一 ⇒ 本轮作废（防"看结果改口径"） |
| **P2 单趟运行与采集** | 采 L1/L2/L3 三纹；记录状态字节数；**不把日志时间戳/墙钟写进指纹**；输出 JSON 用规范序列化（键排序） | 指纹缺 L2 ⇒ 不判 C13；日志字段混入指纹 ⇒ 记录偏差 |

| **P4 4 配置矩阵** | 4 个**独立进程**：`PYTHONHASHSEED∈{0,12345}` × `OMP_NUM_THREADS∈{1,4}`；顺序跑；每配置 1 次（关键交付建议 2 轮） | L1+L2 4/4 全同＝过；任一不同＝FAIL；仅 L3 不同且 L2 同＝记录（同机则追浮点路径） |
| **P5 阳性对照面板** | 见 §5.2 表：换种子／urandom／1 ULP／1 格步／量化前 float32 计算／亚格噪声／半格；另加"同配置重复"必须同 | 换种子必须 L1/L2/L3 不同；1 格步必须 L2 不同；量化前 float32 必须 L2 或 L3 不同（**允许 L1 同**）；亚格噪声允许 L2 同；**任一"应不同却同" ⇒ 检测器失效（U0）** |
| **P6 状态完整性** | ①**断点续跑**：跑 20 拍→快照→重建模型恢复→续 20 拍，与不中断 40 拍比；②**逐数组扰动**：对清单中每个数组注入 1 格步，L2 必须变（漏数组＝不可见）；③**排除项验证**：对声明排除的诊断量注入，L2 允许不变（但断点续跑必须仍同） | ① 不同位 ⇒ 状态清单不完整（INVALID）；② 任一数组扰动 L2 不变 ⇒ 指纹漏项（INVALID） |
| **P7 外部工具臂** | 三分类见 §3：可重放臂按记录-重放判 C13；实时臂只报分布级，**不计入 C13** | 把实时臂算进 C13 ⇒ 违规（U10） |

**四件套**——**主张**：P0–P7 能把"C13 达成"变成可失败判定，且失败模式可区分（数值策略破坏／检测器失效／状态漏项／环境不可复现）。**证据**：本件已按 P2–P6 在 V4 与千层上跑通 [实测]（§0.3、§5.2）。**反证**：任一阳性对照"应不同却同"，或断点续跑不同位。**代价**：单臂 C13 验证 ≈ 4 配置 + 2–3 对照组 + 1 次续跑 ≈ **6–8×单趟墙钟**，内存增量 0（顺序）[实测基准]。

## 3. 含外部工具调用时的确定性（T5/C13 相容口径）

### 3.1 三分类（先分类，再谈确定性）

| 类 | 例子 | C13 口径 | 判据 |
|---|---|---|---|
| **① 纯计算外部件** | 外挂模型/torch/预训练权重 | **禁当器官**（C10）；若仅作对照，必须单列"外部件"、**不计入 AHI 自有 C13** | 单列声明＋资源单列 |
| **② 只读观测** | 截屏（`PIL.ImageGrab`，`真机探头.py:143-150`）、UIA 结构读取 | **记录-重放**或**固定输入流**才可计入 C13；实时只读观测**不计入** | 重放两独立进程 L1/L2 逐位同 |
| **③ 键鼠动作注入** | 鼠标/键盘原语 | 实时注入**物理不可复现**；仅"固定输入流＋回放钟"下动作序列逐位同可计入，且单列为"沙箱 C13" | 动作序列 bytes 逐位同；真实臂单列 U10 |

### 3.2 环境快照（字段清单，见 P0）

操作类工具还必须冻结：**分辨率/DPI/缩放、显示器数、前台窗口句柄与标题、目标应用版本、输入法/键盘布局、鼠标指针初始位置**；沙箱世界对象版本（靶场定义）。缺任一 ⇒ 该轮只能报"分布级"（U10）。

### 3.3 记录-重放协议（可执行口径）

**录**：每个逻辑拍记 `{t_logical:int, 观测帧 sha256＋帧本体（或特征向量）, 注入动作, 系统自观测的成功标志, 该步注入延迟 τ（来自 `时基.回放钟`）, 环境快照 sha256}`。
**放**：新建进程 → 从快照重建沙箱世界 → `钟=时基.回放钟(τ序列)` → 观测从文件逐帧喂入 → 跑同一策略。
**判**：L1 动作序列 bytes **逐位同**；L2 世界/内部状态格上指纹 **逐位同**；L3 仅同机同构建守卫。
**边界（必须写明）**：记录-重放证明的是"**给定同一观测流，决策链逐位确定**"，**不证明**"实时感知/实时世界可复现"——本件实测实时抓屏 3/3 帧不同（§0.3 P-C），故实时臂永远只能是分布级（U10）。
**存储**：原始帧 1920×1080×3 B＝**5.93 MB/帧** [实测]；3 s@30fps ≈ **534 MB/ episode** [推算，与黄队 R1 §6.2 同结论] ⇒ **算不起**；须走**固定合成输入流**或**特征级重放**（压缩率**未测**）。

### 3.4 固定输入流（推荐给 C13 主臂）

用显式种子**合成**观测帧（或合成靶场对象序列），不抓真屏、不依赖前台窗口：成本≈1 帧缓冲，无录制存储；判据同 §3.3 的 L1/L2。**局限**：只证明"决策链对给定输入确定"，不覆盖真实感知；真实感知另立第二臂（U10）。

### 3.5 时间戳剥离（哪些必须剥、怎么剥）

| 原则 | 做法 | 依据 |
|---|---|---|
| 决策路径禁墙钟 | 判据/决策路径**不得**调用 `time.time()`；`perf_counter` 只能进诊断 | `时基.py:12-13`（t_mono 来自 perf_counter／注入钟／回放钟；time.time 永不参与判决）；`判据_三层.py:18` |
| 时间量走可注入钟 | 需要时间处一律 `拍钟(t0=…, 钟=回放钟(序列))` | `时基.py:90-105`（回放钟）、`:117-118`（拍钟可注入） |
| **延迟参与决策时必须重放** | 训练/调度若用"实测耗时"（`技能调度.py:99-157` 的 `耗时列`→档位判定），实时档的耗时是墙钟读数 ⇒ 必须用**回放钟序列**或**逻辑拍数**替换 | `技能原子.py:35-37`（演练＝拍数×100ms 显式时间；真机＝真实经过时间）、`:401-437`（`钟.延迟` 读耗时）；`技能调度.py:105-133` |

### 3.6 诚实不可保证清单（外部工具）

1. **实时世界逐位同：物理不可能**（本件实测 3/3 帧不同；动画/时钟/光标/合成器皆变）⇒ 只能分布级（U10）。
2. **实时键鼠注入时序**不可复现（OS 调度/焦点/防作弊/DPI）；只保证"逻辑动作序列"同，不保证"物理延迟"同。
3. **真实感知**（抓屏、UIA 结构读取）不可回放为"同一感知"，只能把录到的帧/结构当输入数据。
4. **网络/外部 API**：不可复现；本轮排除在 C13 外或单列为外部件（黄队 R1 §6.3-7 同口径）。
5. **记录-重放原始帧**：存储 534 MB/episode 算不起（[推算]）；特征级压缩率**未测** ⇒ 不得写成"可重放"。
6. **外部工具的内存/峰值**：不要求逐位同，只要求两趟 median 差 ≤10%（黄队 R1 §3.1 P2）。

**四件套**——**主张**：含外部工具时，C13 只能主张"**给定录入观测流与回放钟，决策链逐位同**"；实时臂必须单列且不计入 C13。**证据**：抓屏 3/3 不同 [实测]；链上时间口径已支持注入/回放（`时基.py`）；调度确在消费实测耗时（`技能调度.py`）。**反证**：若实时臂两趟逐位同 ⇒ 环境恰好确定，记录但不改变口径；若重放臂 L1 不同 ⇒ 记录-重放无效。**代价**：固定输入流≈0 存储；原始帧重放 534 MB/3s 算不起 [推算]；抓屏 36–61 ms/帧 [实测]，不得置于决策热路径。

## 4. 跨进程/跨硬件边界

### 4.1 边界矩阵

| 边界 | 可主张 | 本件实测/依据 | 判据 |
|---|---|---|---|
| 同进程两次 | **是**（弱口径，不够） | 现有判据即此 `判据_V4_两区室核.py:312-319` | 只作冒烟 |
| **同机跨进程** | **是（C13 最低达标口径）** | 本件 4 配置 / 千层 2 配置全同 [实测]；R1 3 配置 [实测] | L1∧L2 全同 |
| 同机跨 `PYTHONHASHSEED` | 是（读序无依赖） | 0/12345 全同 [实测] | 同上；不同 ⇒ 追顺序依赖 |
| 同机跨 BLAS 线程数 | 是（该路径） | OMP 1/4 全同 [实测] | 新内核需重测（不得外推） |
| 同机跨 numpy 版本 | **未测/不可主张** | 规约分组可能随版本变（`np.mean` 等） | 升级即重跑全量 C13 |
| 跨 CPU 指令集（AVX2/AVX512） | **未测/不可主张** | 量化只**概率性**吸收 ULP；边界不连续（见 4.2） | U5；需第二台机器实测 |
| 跨 OS/跨构建 | **不可主张** | 未测 | U5 |
| GPU 引擎 | **不可主张** | 未测；cuBLAS 归约非确定（无 deterministic 声明） | 单列外部件 |
| 含实时外部世界 | **不可主张**（只分布级） | 抓屏 3/3 不同 [实测] | U10 |

### 4.2 为什么"跨硬件"不能靠 2^-20 量化"证明"（概率模型，[提案/未验证]）

- **实测事实**：量化器**不连续**——相邻两个 float（相差 1 ULP）跨在格边界两侧时，输出相差**整整 1 个格步（2^-20）**（本件边界探针：`boundary_flip=True` [实测]）。因此"亚格噪声必被吸收"不成立；它只在**不跨边界**时吸收（P-A3：P 乘 `1+1e-9` 被完全吸收；加半格则 L2 变）。
- **漂移模型 [提案/未验证]**：设一次量化事件的预量化漂移为 `E`、格步 `δ=2^-20≈9.54e-7`，则单事件跨界概率 ≈`E/δ`。对 800 拍 V4 路径，量化事件量级 `N≈10^6`：`E=1e-16`（1 ULP 级）⇒ 期望跨界 `≈10^-4`；`E=1e-13`（长链累积/不同 FMA 融合）⇒ `≈0.1`。**`E` 是跨硬件未知量 ⇒ 无法给保证**；只能上第二台机器实测，或整数化。
- **结论**：对外只写"同机跨进程逐位同（已实测）；跨硬件未测、不主张"（U5）。**禁止**用"设计上量化会吸收"替代实测。

### 4.3 若要跨硬件逐位（第二轮候选，本轮不做）

把唯一的高风险浮点路径整数化：`P @ 特征(x)`（`算子_两区室核.py:175,179`）与千层 `np.mean/np.std` 规约（`算子_千层骨.py:415,420,509-534`）改为 int64 定点乘加/整数化归约（`读/叠` 已是 int64 精确，可复用口径）。收益：跨硬件可证；代价：乘加增加（量级 `D×3/拍`，D=256 ⇒ +768 乘加/拍；相对 V4 每拍量级 O(10^3) ⇒ 估 +30%~50%）[未验证]；属**改既有件**，需主控备份授权，本轮**只登记不改**。

**四件套**——**主张**：本轮 C13 的最高可主张范围是"同机跨进程"；跨硬件/跨版本/GPU 全部不可主张。**证据**：4 配置与千层 2 配置全同 [实测]；边界不连续 [实测]；P@φ 为 BLAS matmul 风险点 [实测/静态]。**反证**：第二台机器实测同 ⇒ 可扩主张（须同时报 L2 与硬件信息）；整数化后跨机 L2 同 ⇒ 强主张。**代价**：整数化 +30%~50% 乘加 [未验证]；跨机器验证需第二台机（未测）。

## 5. "缺阳性对照"怎么补（直接回答 R1 §8.2 的缺口）

### 5.1 R1 缺口的三层

1. **检测器灵敏度**：4 配置全同，可能是"真确定"，也可能是"指纹/采集坏了"。⇒ 必须有一个**应不同而不同**的注入。
2. **状态完整性**：全状态指纹若漏掉某个可变数组，两趟仍可能同（该数组恰好也没变），但这是**盲区不是确定性**。⇒ 必须证明"清单里每个数组都影响指纹"（逐数组 1 格步扰动）+ "清单整体足以续跑"（断点续跑）。
3. **读序合规性**：HASHSEED 不同仍同，可能是"代码无顺序依赖"（合规），也可能是"没读到那条路径"。⇒ 静态审计（集合遍历转 sorted）+ 动态 HASHSEED 差，二者同报，**不要求"必须不同"**（修正 C）。

### 5.2 阳性对照面板（本件已实测；判定写在表内）

| # | 注入 | 构造（仅测试期，内存 monkeypatch，不改文件） | 期望 | 本件实测 | 若不符 ⇒ |
|---|---|---|---|---|---|
| PC-1 | 换种子 | 模型种子 47001→47002 | L1/L2/L3 **必须全不同** | 全不同 ✓ [实测] | 检测器或种子通道失效（U0） |
| PC-2 | 无种子随机源 | `int.from_bytes(os.urandom(4))` 作种子 | 必须不同 | 不同 ✓ [实测] | 随机源未进状态或检测器失效 |
| PC-3 | 1 ULP 状态注入 | `np.nextafter(读出[0,0], +inf)` | L3 必须不同；**L2 允许同**（量化吸收） | L3 不同、L2 同 ✓ [实测] | L3 不变 ⇒ 指纹盲区 |
| PC-4 | 1 格步注入 | 状态元素加 `2^-20` 再回格 | L2/L3 **必须不同** | 均不同 ✓ [实测] | 指纹漏项/检测器失效 |
| PC-5 | **量化前 float32 计算注入**（修正 A 的正确形态） | 测试替身 `_归'`：先 `float32` 计算再 `rint(x·2^20)/2^20`；替换模块级 `_归` | **L2 或 L3 必须不同；L1 允许同** | L2/L3 不同、L1 同 ✓ [实测]（Acc 仍 0.8938） | 若 L2/L3 也同 ⇒ 先加大注入（float16 或 `×1.01`）复测；仍同 ⇒ 检测器失效（U0）；若加大后不同 ⇒ 记录"该强度以下被量化吸收" |
| PC-6 | 亚格噪声（应被吸收） | `P ← P·(1+1e-9)` | L1/L2 可同（记录"被吸收"） | 同 ✓ [实测] | 若不同 ⇒ 边界跨越，记录（不做失败） |
| PC-7 | 半格注入（边界侧） | `P ← P + 2^-21` | L2 可不同；L1 可同 | L2 不同、L1 同 ✓ [实测] | — |
| PC-8 | 同配置重复 | 同进程再建一次 | 三纹**必须全同** | 全同 ✓ [实测] | 有隐藏状态/缓存污染 |
| PC-9 | 读序审计（修正 C） | HASHSEED 0 vs 12345 | 当前实现应**同**（合规记录）；不同 ⇒ 查顺序依赖 | 同 ✓ [实测] | 不同 ⇒ 找到顺序依赖并修，不是判 INVALID |
| PC-10 | 断点续跑（完整性） | 20 拍快照→恢复→续 20 拍 | 续跑决策/终态**必须同** | 同 ✓ [实测]（V4） | 状态清单不完整（INVALID） |

**判定汇总**：`PC-1/2/4/5/8/10` 是**必过项**；`PC-3/6/7/9` 是**记录项**（允许同，但必须解释）。任一必过项失败 ⇒ C13 判 `INVALID`（U0），本臂读数作废。

### 5.3 对 R1 §8.4 三条注入的处置建议

- `np.float32 中间态`：改为 PC-5（量化前计算注入），期望改为"L2/L3 不同、L1 允许同"（修正 A）。
- `os.urandom 种子`：保留为 PC-2（必过）。
- `dict 顺序依赖`：降级为 PC-9 读序审计（修正 C），不作为"必须不同"。

**四件套**——**主张**：补阳性对照后，C13 从"两趟碰巧一致"升级为"检测器有灵敏度 + 状态清单完整 + 读序无依赖"三件可失败结构。**证据**：PC-1~10 本件实测（§5.2）。**反证**：任一必过项失败 ⇒ INVALID；断点续跑不同位 ⇒ 清单不完整。**代价**：每臂 +3–5 次单趟（V4 0.11–0.14 s/趟；千层 1.2–2.2 s/趟）[实测]。

## 8. 资源口径与确定性冲突（两趟计费 / 峰值叠加）

### 8.1 分项（口径分离；实测与推算分开）

| 方案 | 墙钟倍数 | 峰值内存增量 | 存储 | 依据/标注 |
|---|---|---|---|---|
| 顺序两趟（推荐） | **×2** | **0**（只留 32 B 指纹） | 32 B/趟 | V4 800 拍 0.11–0.14 s/趟 [实测]；黄队 R1 §3.1 P4 同口径 [文献类比] |
| 4 配置矩阵 | ×4（顺序进程，峰值不叠加） | 0 | 4×指纹 | 本件 4/4 [实测] |
| 阳性对照面板 | +3–5 单趟 | 0 | KB | 本件 PC-1–10 [实测] |
| **并行两趟**（不推荐） | ×1（同时） | **+第二份全状态**：V4 **0.16 MB** [实测]；千层 D=64 **6.56 MB** [实测]；D=256 未测 | — | 黄队 R1 §3.2 报 +16.29 MB 为 D=256 **引擎参数/状态**口径 [文献类比]，与本件 D=64 实测不可直接混用 |
| 断点续跑校验 | +1 单趟 | +第二实例（同上） | 序列化 0.16 MB（V4）/6.56 MB（千层 D=64）[实测] | 本件 P-A4/P-B |
| 记录-重放（原始帧） | ×2 | +1 帧 5.93 MB | **5.93 MB/帧** [实测]；3 s@30fps≈**534 MB** [推算] | 黄队 R1 §6.2 同结论；**算不起** |
| 固定合成输入流（推荐） | ×2 | +1 帧≈5.93 MB | ≈0（种子生成） | 本件 §3.4 [提案] |
| 特征级重放 | ×2 | +特征缓冲 | 压缩率**未测** | U-D4 |
| 抓屏仪器 | 不计入决策路径 | — | — | 36–61 ms/帧 [实测]；`nvidia-smi` 61–117 ms [黄队实测]，禁入热路径 |
| 全状态哈希 | +8.1–13.0 ms/趟（千层 6.56 MB）[实测]；V4 0.16 MB 未单独测 | 0 | — | — |

### 8.2 三个直接回答

1. **两趟是否重复计费？**
 - **本地 CPU**：无对外计费；但**墙钟 ×2**，且 C13 验证（4 配置＋对照＋续跑）≈ **6–8×单趟**，必须**单列为"验证开销"**，不得摊入功能判据预算，也不得把第二趟算作"第二个实验样本"（防用重复趟数冒充 n）。
 - **含外部调用**：实时第二次调用＝外部成本×2 且不可复现；应用**记录-重放**作第二趟（外部调用 0 次），否则按 2× 计并标 U10。
2. **峰值是否叠加？**
 - **顺序两趟/4 配置（顺序进程）**：**不叠加**——进程级 `peak_wset` 取单趟最大，不是求和。
 - **并行两趟**：叠加"第二份全状态"（V4 0.16 MB、千层 D=64 6.56 MB [实测]），**不推荐**。
 - **记录-重放**：叠加帧缓冲/存储（5.93 MB/帧；3 s 原始帧 534 MB [推算]）⇒ 用固定合成输入流替代。
3. **"确定性"本身要不要进账？**
 - 要：哈希/序列化/环境快照/4 进程启动都是**测量成本**；按本件实测单趟（V4 0.11–0.14 s、千层 1.2–2.2 s）＋ numpy 导入 0.22 s/进程（黄队 R1 §1.1）推算：V4 全链 C13 ≈2 s、千层 30 拍级 ≈8–12 s [推算]。相对判据墙钟（千层 21 臂 8 min、V4 16 臂 0.12 s 级）可忽略，但**必须列**，否则"更小资源"的账会把验证成本漏掉（红队 T2 攻击面）。

### 8.3 建议冻结的预算口径（[提案]）

- **C13 验证预算单列**：`T_C13 ≈ 6–8 × T_单趟`（含 4 配置、对照、续跑），不并入功能臂预算。
- **内存**：顺序两趟不计增量；并行/续跑只计第二份**全状态**（V4 0.16 MB；千层 D=64 6.56 MB [实测]）。
- **存储**：指纹 32 B/趟；状态快照按"全状态字节数"计；禁止把原始帧重放写进"可跑"方案（534 MB/3s）。
- **外部调用**：C13 第二趟一律走重放；实时臂单列、不计入 C13，也不计入"确定性达成"。

**四件套**——**主张**：确定性的成本是"墙钟×2/×4 + 秒级哈希 + 可选第二份状态"，**不是**内存翻倍；但 C13 验证总量必须单列 6–8×，否则资源账失真。**证据**：本件 §8.1 实测分项；黄队 R1 §3.1 P4/§3.2 对账。**反证**：若实测并行两趟峰值增量≠第二份全状态，或顺序两趟峰值>单趟，则口径需重定。**代价**：见 §8.1；外部帧存储 534 MB/3s 算不起 [推算]。
