## 0. 一句话

P0 问「信息放在哪里」：窄递归状态（1024）单独回读，是否不如「窄状态 + 离散锚点/账本旁路」，以及离「宽状态上界」有多远；

## 1. 双集 / sham / 确定性 / 铁律

- **双集**（沿用测量台）：判据集 `seed 0–5`；留出集 `seed 6–11`。阈值只看开发集（100–103）校准，**不得看留出集来定**；两集都过才算过。
- **sham**：主臂必须过、同形零假设臂必须不过（`测量台.注册(..., sham=...)`），防恒真判据。
- **确定性（C13）**：随机只来自 `np.random.default_rng(显式种子)`；数值走 `_归` 的 2^-20 定点格；同种子两趟逐位同（测量台内置 + 判据显式复核）。

- **C14（不破既有）**：只新增 `meeting57/`；只读 import `meeting40/实施/测量台.py`、`meeting41/实施/算子_能力核.py`；不修改 V3/V4 任何既有 `.py`；`AHI4/AGENTS.md` 的登记**改前备份**到 `meeting57/备份/`。

## 2. P0 · 信息保留位置消融

### 2.1 合成任务（`实施/环境_长程合成任务.py`）

- 192 个细节事实（每个 4 bit 值域 0–15），在步 0–191 逐个声明；
- 长程目标 `goal` + 约束 `constraint` + 实体 `entity` 三个关键锚点贯穿全程；
- 延迟回查：每个细节在 Δ ∈ {8, 48, 96} 后回查；
- 矛盾注入：16 个细节各有一条低权限「传闻」+ 一条高权限「更正」（真值不变）；goal 另有一条低权限流言 + 高权限更正；
- 干扰分支：每步 2 条干扰写入 + 16 条干扰键查询（正确回答=「未知」）；
- 真值规则：`max(权限, 步, 序号)`（权限优先，同权限取更新）；**每条查询有已知真值**；
- 规模：T≈293 步、约 815 事件、约 626 查询；CPU 单臂约 0.1 s 量级。

### 2.2 四臂

| 臂 | 记忆载体 | 目的 |
|---|---|---|
| A | 纯窄递归状态（D=1024）：所有事件写进同一叠加态；解绑 + 硬阈值迭代吸引子回读 | 基线：只靠向量记 |
| B | 窄状态 + 离散锚点/账本旁路：任务相关事件原样入账；按 (权限, 步) 受控回读；干扰键不入账 | 测「关键信息不压缩」 |
| C | 宽状态/无瓶颈上界：每键一个 1024 维独立槽位；精确回读 | 上界对照，**不是目标架构** |
| S | B + sham：随机锚点（写入即随机）/ 打乱账本 / 惰性回读 / 缺失回读 | 零假设对照 |

### 2.3 指标

1. 延迟细节召回率（按 Δ=8/48/96 分列；主指标=全部细节查询）；
2. 长程目标正确率 + 最长连续保持步数；
3. 矛盾注入后污染率（回答=矛盾流言值）与矛盾错误率；
4. 关键槽位回读保真度（goal/constraint/entity 每步）；
5. 干扰键拒答率（正确=未知）；
6. CPU 时间 / 峰值内存（判据外测量；内存 < 2 GB）。

复合分（P0 主汇总）= `mean(延迟召回率, 目标正确率, 关键槽位保真度, 1−矛盾污染率)`。

## 3. P1 · 内部仲裁隔离

### 3.1 合成任务

同一 `环境_长程合成任务.py` 的 P1 档：T=72；8 个细节、2 个矛盾细节；低权限流言 + 高权限更正；goal 在步 40 有一次**合法高权限更新**；每步后做 3 轮「自省」（无新证据），在自省轮里探测稳定键的报告。

### 3.2 三臂（同一连续状态 D=2048；存储容量刻意不是瓶颈，隔离仲裁变量）

| 臂 | 仲裁方式 |
|---|---|
| A′ | 同一连续状态连续自省：事件直接写入；每轮自省把当前读回再写回（自指回路），无独立审判 |
| B′ | 事件触发：只读快照 → 独立审判器（权限优先/同权限取新/冲突拒绝低权限）→ 受控写回；无新证据时不写 |
| S′ | B′ 架构 + 惰性/sham 审判：不看权限、按新近接受（或惰性跳过），其余同 B′ |

### 3.3 指标

1. 语义漂移率：无新证据的自省轮里，稳定键报告相对本轮事件后基线的改变率；
2. 震荡幅度：探测键报告序列的翻转率（连续报告改变次数 / 转移数）；
3. 冲突后错误率：低权限流言/合法更新之后、更正之前，报告 ≠ 当时权威真值的比例；
4. 错误传播率：低权限流言值在后续报告中的占比；
5. 更正延迟：高权限更正后到首次正确的报告轮数；
6. 复合仲裁分 = `1 − mean(漂移率, 震荡幅度, 冲突后错误率)`（主汇总；各分量同时报告）。

### 3.4 冻结判据（P1；方向先冻结，数值在 P1 判据顶部写死后再跑）

- **P1-1** B′ 语义漂移率显著低于 A′（6/6，`p<0.05`）；
- **P1-2** B′ 震荡幅度显著低于 A′；
- **P1-3** B′ 冲突后错误率显著低于 A′（差值 ≥ 0.10）；
- **P1-4** B′ 复合仲裁分显著高于 A′（差值 ≥ 0.10）；
- **P1-5** B′ 冲突后错误率/震荡显著低于 S′（证明收益来自审判器，不只来自冻结）；
- **P1-6** sham 无效：S′ 相对 A′ 的复合分无显著提升（`p≥0.05` 或 `均值差≤0.02`）；
- **P1-7** 双集 + 两趟确定性 + C1 + 仪器自证（oracle 仲裁满分、空臂失败）同上。
- **不假设**「更深/更多自省步数更好」；假设是「隔离优于连续自省」。若 B′ 不优于 A′，如实登记证伪。

### 3.6 实施期口径登记（如实披露，不改预注册原文）

1. **语义漂移率主口径**：实施为「已就绪稳定键的报告 ≠ **本轮事件后权威基线（真值）**」的比例；预注册 §3.3 字面写的是「相对本轮事件后基线（自身基线读）」。两个口径都上报：`语义漂移率`（事件锚定/权威基线）与 `语义漂移率_同轮`（相对自身基线读）。
   - 严格同轮口径下，A′/B′/S′ 在判据集/留出集全部 12 种子恰为 **0.000000**（自指回写是定点，轮内不改变自己的报告）⇒ **若严格按预注册字面口径，P1-1 会 FAIL（0 对 0）**。
   - 主判据 P1-1 PASS 用的是事件锚定口径（A′ 0.855/0.856 vs B′ 0）。两口径并列，不得只引 PASS 的那个。
2. **P1-2 的失败是结构性的，而且阈值低于指标分辨率**：指标分辨率 = 1/753 ≈ 0.001328（B′ 的实际值就是 1/753）；A′ 自指回写=定点 ⇒ 震荡恰为 0；B′ 的 0.0013 就是步 40 合法更新造成的**一次**翻转。**仪器 oracle 的震荡也恰为 0.001328** ⇒ 该指标把合法更正计为不稳定。冻结阈值 0.0005 低于分辨率，且 dev 校准已显示 A′−B′=−0.001328（4/4）⇒ 该条在开跑前即注定 FAIL。**「连续自省 ⇒ 震荡更高」在本任务被证伪**，且与 A′ 是否幻读无关（公平基线 A′_有据 的震荡仍为 0）。
3. **Post-hoc 公平基线诊断（仅 dev 100–103，不替换主判据）**：A′_有据（同构 A′，仅不对从未收到任务相关事件的键自省回写）dev 均值：漂移 0.2042、震荡 0、冲突错 0.3929、复合 0.8010；B′ 仍 4/4 方向占优，S′ 相对 A′_有据则更差（复合 −0.0944、冲突错 −0.3929）。⇒ **主判据 P1-6 的失败主要由 A′ 的幻读自固化驱动**；公平化后 dev 上 P1-6 会 PASS。主判据仍按原冻结 A′ 口径判 FAIL；dev n=4，方向一致不等于显著。详见 [`实施/诊断_P1_公平基线.md`](实施/诊断_P1_公平基线.md)。
4. **P1-1 的 PASS 依赖自省强度=1.0（未在预注册披露，补登记）**：dev 自省强度扫描：0.1 → A′ 漂移 **0.1633 < 0.20 门槛**（P1-1 会 FAIL），复合 0.7902；0.5/1.0 → 漂移 0.8302、复合 0.5447；2.0 → 漂移 0.7083、复合 0.5853。冻结 1.0（与事件同权）是**跑前选择**，但 P1-1 PASS 不是对强度不敏感的稳健结论。
5. **P1 阈值时间线**：Lead 在 10:52:22 观察到 `开发_校准_P1结果.json` 存在（早于判据 10:53:15、结果 10:54:43）；随后 post-hoc 诊断在 10:56:53 追加/覆盖该 JSON，故独立复核只能看到更晚的 mtime，无法从现存文件证明「阈值确由 dev 校准产出」。可证实的是「阈值常量在最终双集跑前已写在判据顶部」；本条如实登记，不宣称不可复核项已被证明。
