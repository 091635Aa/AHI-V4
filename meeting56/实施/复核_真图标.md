## 三、发现的问题清单（按重要度）

**P1（必修）R3 文档数字与结果 JSON 失同步。**
- 文档 §13.3（`00_应用_想象画面_从人脑到AHI4.md` 第 475 行，复核时 sha256 `8A367434…`）与任务描述：`972 .784 / 束 .7887`。
- 结果 JSON：`R3_类别识别.轮廓码972.平均=0.8324`、`形状束1024.平均=0.8296`；我独立复算 = .8324/.8296。
- JSON 中**不存在** .784/.7887（全量数值扫描）；我另测 5 种可能口径：7 类原型留一 .8732/.8592、11 类原型留一 .8456/.8188、11 类 10 探针 .8121/.7933、轮廓口径 .6915、149 全类库评估 7 类 .8113/.8042 —— 都不等于 .784/.7887。
- 同段"类内混淆"也是旧数：文档 Word→Excel 16 / Excel→Word 15 / PDF→Word 9 / 白页→系统 10；JSON 实为 **17 / 18 / 13 / 1**（白页→文件夹才是 10）。
- 结论：R3 是**旧版残留**，实际数字略高于宣称。**对外必须改引 JSON 值**（".784/.7887"改成".8324/.8296"），混淆计数同改。

**P2（必修）人工标注 2 格错标为"非图标"。**
- k=143（r8c8，格框 608,792）实际是「文件批量重命名.exe」图标；k=151（r9c2，格框 152,892）实际是「UninstallT…」图标。两者都在`标注页_3.png`里被画成图标却标了"非图标"；它们的检出密 .3987/.3759、字框 50×49/47×52，是**真阳性**。
- 影响：①精确率 .903 → **.9152**（151/165）；②"壁纸误检 16 格"应为"14 壁纸 + 2 未登记图标"；③16 格反例表里这两格相似 .650/.645，说明它们不是壁纸，而是"未入簿真图标"（被门正确拒绝，结论 0/0 不变）。
- 建议：修正 `标注_真图标.json` 这 2 格（类=应用），重跑实验，同步改 R1/R5 文字；R2/R3/R4/R6/R9 的 149 原型集会变成 151，需要重算（预计小幅变化）。

**P3（口径）"972 轮廓码 vs 1024 形状束"不是两种独立表示，而是同源统计的两种取码。**
- `形状束.py` 内部特征 = 3 阈值 × (16²+8²+2²) = **972 维**（注意：该文件 docstring 写"204 维"是过时注释；代码实际 `for n in (16,8,2)`，既有件不改，但引用时别照抄 204）。
- `码_972` = 这组 972 维特征的 L2 归一化（输入同为边缘色差图 E；量化差 cos≥.99924）；`码_形状束` = 该特征经 `共存态.编码.特征码` **随机投影(972→D=1024)+sign 二值化**。所以 R2/R3/R4 的"两表示对照"实际是"信息保留版 vs 随机投影二值版"，差异主要来自投影/二值化损失，不是两条独立视觉通道。这不推翻结论（既有形状束确实能用），但"对照"的说法要降级为"同族取码对照"。

**P4（口径）R6 的"想象→识别 11/11"是闭集自洽（近乎同义反复），不能当"能认出实例"的证据。**
- 书里存的 972 码就是 `码_972(类原型轮廓)`；想象在活度 1.0 时输出=原型轮廓本身 ⇒ 查询码与库码**逐位相同**，我实测自相似 min=max=**1.000000**，11/11 是恒等命中；活度 .45/.2/.12 自相似降到 .68/.52/.41（仍 11/11、.12→9/11），只说明 972 码对稀疏化稳健，不是"想象出实例再去认"。
- 复核者加测（更接近"认实例"）：类原型的稀疏想象 → **149 个实例轮廓 972 码**最近邻（留一排除原型自己）只到 **6/11**（1.0/.45/.2）、**5/11**（.12）。⇒ 建议把 R6 改述为"闭集类原型自洽性"，并附这条加测。

**P5（口径）R2 平均被平移臂明显拉低，建议单列。**

**P6（口径）"跨裁剪一致率 .942"是格级、半格容差、同像素基线，不是框级/像素级一致。**
