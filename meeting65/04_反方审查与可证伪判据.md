## 1. 对「LST 机制可迁移」的对抗审查（8 条）

> 每条格式：**主张**｜**最可能错在哪**｜**如何证伪（什么读数出现就判错）**｜**需要什么对照**。

### R1 收益可能主要来自预训练数据/规模，patch 聚合只是「省算力的形状」

- **主张**：patch 聚合本身提升能力（+6.5% speech HellaSwag）。
- **最可能错在哪**：论文全部对照建立在 **1.8T 文本 token、约 16.5 万小时语音（44,174+14,699+50,601+55,309，Table 1）、HuBERT 501×25Hz 分词器、420M–7B Transformer** 之上 `[文献]`（§4.1 第 5–6 页、§2 第 3 页、Table 1 第 6 页）。增益是「这个基底 + patch」相对「这个基底」的差分，不是「patch 相对无 patch」的普适增量。AHI4 没有预训练、没有 LM、没有神经分词器、没有梯度训练（AGENTS 诚实边界：D=256 玩具级），差分赖以存在的基底不存在。
- **如何证伪**：在本载体上跑探针，若 A2（真 patch）**不优于** A0（帧级）/A1（音节级）基线（§3 阈值 P1 失败），则「可迁移」在本载体上**不成立**，不得以「规模大了就会好」外推——按本仓纪律，规模效应未测即未测。
- **需要什么对照**：①同算力/同 readout 的无聚合基线（A0）；②同压缩比的**朴素压缩对照**（A8 定长分块）——它就是 LST 的 BPE 基线的本仓等价物：**BPE 也缩短序列（8.2% 算力节省），但 HellaSwag 39.4 < 基线 40.2** `[文献]`（Table 4 第 7 页）。这条反例说明「序列变短」本身不产生能力，活性成分必须是「有界上下文聚合且保信息」。

### R2 把「序列变短」误当「表征更好」

- **主张**：LST「reduces the effective AR sequence length … without degrading reconstruction quality」。
- **最可能错在哪**：摘要把两件事混在一句：**效率**（context units 0.25×、generation units 0.25×）与**质量**（CER）。逐表核对：
  - TTS：baseline 20k CER **14.1 / 15.1**，LST 20k **14.1 / 16.2** `[文献]`（Table 5 第 8 页）⇒ clean 持平，**other 反而差 1.1**。摘要的「without degrading」在 other 子上不成立。
  - ASR：baseline 1k 步 WER **140 / 202**，2k **44.7 / 73.2**，4k **20.7 / 42.4**；LST 1k **6.8 / 10.4** `[文献]`（Table 5）。原文同时自述 baseline「frequently hallucinates … unreliable stopping behavior」⇒ 这是**基线训练崩了**的对比，不能当作「patch 表征更好」的证据；它最多说明「patch 让 ASR 适配更稳」。稳定化 ≠ 表征更强。
- **如何证伪**：若一个「训练稳定性已匹配」的对照下增益消失（本仓探针所有臂共享同一 readout、同一训练量、同一特征预算，只变单元粒度），则增益归因于稳定性/算力而非表征。
- **需要什么对照**：收敛性控制（训练 loss/验证曲线同区间）+ 同 readout 消融 + 把「效率」与「质量」两个指标分开报告，禁止用一个指标证明另一个。

### R3 learned patch encoder 不可替换为确定性分段＋统计聚合（**最致命的一条**）

- **主张**：「LST 的 patch 聚合可以用确定性分段+统计聚合实现」（简报 §7「需改造」）。
- **最可能错在哪**：LST 的聚合器是**学出来的**：`PatchEnc(X_{P_i})`＝一串**滑窗自注意力 + 交叉注意力层** `[文献]`（§3.1 第 4–5 页、§3 第 4 页）。附录 A.2.1（第 14 页）补充得更清楚：交叉注意力的 patch query **只是用「span 内 token 隐状态的池化」初始化**，随后由注意力用 token 特征做 keys/values **精修**，整体是「token → 潜变量 patch → token 的信息瓶颈」；论文自述「This mechanism is central to LST's ability to reduce effective sequence length … without sacrificing … fidelity」`[文献]`。关键点：**「池化」只是初始化，不是机制本身**；论文**没有**「把 patch encoder 换成均值/统计池化（不精修）」的消融。它的 BPE 对照（学习式分词合并，另一条压缩路线）**失败了** `[文献]`（§5 第 7 页）。
  因此：论文证明的是「学出来的有界上下文聚合 + 瓶颈」有用，**没有**证明「任何压缩聚合」有用。AHI4 只能做确定性统计（均值/方差/首末）＝**只有初始化、没有精修**的那个版本——这正是论文缺失的消融，也是最容易掉点的一侧。
- **如何证伪**：探针 **A3（打乱 patch 边界）** 与 **A4（随机 patch 长）** 是这条的杀手臂：
  - 若 A2 ≈ A3 ≈ A4 ⇒ 边界不携带信息，所谓「分段聚合」退化为**对顺序不敏感的全局统计**，与 LST 的「有界上下文」机制不是一回事 ⇒ 判「换了机制」，不得称「迁移」。
  - 若 A2 明显 > A3/A4 但 A2 仍不优于 A1 ⇒ 分段结构有信息，但不足以超过 AHI4 自带的音节单位 ⇒ 结论是「AHI4 已有更合适单位」，不是「LST 可迁移」。
- **需要什么对照**：①打乱边界臂（A3）；②随机 patch 长臂（A4）；③定长分块臂（A8）；④**顺序敏感对照**（把 patch 内帧序打乱后重算统计，若读数不变则统计量本身对顺序不敏感——这是"确定性统计"的固有属性，必须如实登记）。

### R4 静音折叠在中文连续语音上可能无效（且「静音」口径先打架）

- **主张**：patch 能「compactly capture recurring acoustic patterns such as silence」，中文上也一样。
- **最可能错在哪**：①LST 的静音处理来自 **aligned patching**：把文本 span 之外的帧**单独成 patch**，静音 patch 平均 **3.7 token（≈148ms）**，比词 patch 的 5.8 token 更短 `[文献]`（附录 A.7，第 17 页；同一统计亦见第 10 页）——它是「隔离静音」，不是「把长静音折成一个巨块」；②AHI4 的「静音」两个口径差 2.8×：判据 v9 的 E1 臂（波形 10ms RMS 低于峰值−40dB 的比例）＝**0.0672 / 0.0633 / 0.0978** `[实测]`（`meeting64/产物/判据/判据_发音_v9.json`），而 E2 探针按帧计划 `声源==-1` 计＝**0.1898 / 0.1094 / 0.1247** `[实测]`（`meeting65/产物/E2/读数_序列基座.json`）。同一句（你好，我是EmoCompanion。，种子 300）一个 6.7% 一个 19.0%，**差 2.8 倍**。口径不统一时，任何「静音折叠能省 X%」的论证都不可比。
- **如何证伪**：探针 **A5（关闭静音折叠）**：若 A5 与 A2 的准确率差 ≤0.02、且 patch 数只差 ≤2 个/句，则「静音折叠」在本载体上**无功**，只能作为表示层的压缩笔记而不是机制。按 E2 段表实测，把每句静音折成单 patch 只省 **10.3–22.2%** 的**段数**（句1 静段3/9 段⇒省2=22.2%；句2 4/29⇒10.3%；句3 9/37⇒21.6%）`[推导]`（E2 读数），但**不省帧数**（时间轴不变）、也不省引擎算力（无 AR，E2 §3.5 已证）；而 AHI4 真正的 12.4× 压缩来自「10ms 帧→段」（931 帧/75 段），与静音无关。
- **需要什么对照**：①折叠/不折叠（A5）；②静音口径统一表（波形 dB 口径 vs 帧计划口径，两者都报）；③中文**短隙**静音（音节间 30–100ms）与**长静音**（句间 >150ms）分开统计——只折叠长静音、短隙不折，才是可迁移的那一半；④**顺序不敏感检验**：本探针的统计描述子对 patch 顺序不敏感，所以「折叠非相邻静音」在读取侧是免费的——这既是它的好处，也是它**不构成序列机制**的证据（见 R3）。

### R5 单位尺度映射错了：LST 的 patch ≈ AHI4 的**音节**，不是「子音节段」

- **主张**：把「token→patch」搬到 AHI4，落点是「音节/patch 单位」（简报 §8.2 把两者并列）。
- **最可能错在哪**：按时间尺度换算，LST 的 patch 与 AHI4 的音节几乎是同一尺度：
  - LST：HuBERT 25Hz（40ms/token）；static p=4 ⇒ **160ms**；词级对齐 patch 平均 5.8 token ⇒ **232ms** `[文献]`（§2 第 3 页、附录 patch 长度统计）。
  - AHI4：音节率 4.38–5.13 音节/s ⇒ **195–228ms/音节** `[实测]`（v9 E4 臂：4.38 / 4.79 / 5.13）；E2 实测「帧每音节」均值 **20.92 帧 = 209ms** `[实测]`（E2 读数）。
  - 而 AHI4 的「确定性分段」实测平均 **13.04 帧 = 130ms/段**（931 帧/75 段）`[推导]`（E2 读数）——**它比 LST 的 patch 更细**。
- **因此**：探针里「patch 级（段）vs 音节级」的对比，实际是「**比 LST 更细的单位** vs **LST 同尺度的单位**」。若 A2 不赢 A1，**不证伪 LST**，而是说明「LST 的 patch 尺度在中文里已由音节免费给出」；若 A2 赢 A1，说明中文的 LST-analogue patch 该更细，仍是「需改造」而非「直接借」。两种结果都支持同一个裁决：**可迁移的是「单位粒度要抬到文本尺度」这一条，不是「patch 聚合」这个实现**。
- **如何证伪**：报告时必须用 **ms 标尺**而不是「帧/token 数」比较（本仓帧 10ms vs LST token 40ms，直接比数字会错 4 倍）。若出现「AHI4 patch 比 LST patch 更省」的结论，先检查是否把 10ms 帧和 40ms token 混算。
- **需要什么对照**：①音节臂（A1，LST 同尺度）；②段臂（A2，更细）；③**跨音节/词级臂（A9，更粗）**——只有 A9 才是严格意义上「比 LST patch 更高层」的单位，但本仓现有数据只到音节，A9 本轮**未测**（§6）。

### R6 「对齐」在 AHI4 是免费的，因此 LST 最赚钱的 aligned/curriculum 在 AHI4 没有独立贡献

- **主张**：patch↔文本单位对齐能带来额外收益，值得迁移。
- **最可能错在哪**：LST 的 aligned patching 需要 **Wav2Vec2+CTC 强制对齐**（外部权重！论文自述「requires an auxiliary model at inference, introducing possible errors」`[文献]` §3.1 第 5 页），所以它才要 curriculum 来「在推理时去掉对齐」。而 AHI4 的**音节边界来自文本/音韵本身**（`音韵_v5.解析音节`，`韵律_v8.建帧` 直接按音节出帧）——对齐是**免费的、100% 准的**。换句话说，LST 花钱买的东西，AHI4 本来就有。对齐在 LST 里的实测增量也很小：Curriculum 45.5 vs Static 44.3（HellaSwag S→S）＝**+1.2**；Table 6：Align(sil sep.) 60.3 vs Static(6) 58.7 = **+1.6** `[文献]`（Table 3/6，第 7–8 页）。这个量级（1–2 个百分点）在 63 项探针上**小于 1 项的分辨率**（1 项=1.59%）——也就是说 AHI4 的探针没有能力分辨 aligned 相对 static 的增量，不要指望在本载体上复现它。
- **如何证伪**：若探针 A1（音节级＝免费对齐）已经≥A2（更细段级），则「对齐/单位粒度」两条都已被 AHI4 现有结构吸收，LST 的增量只剩「learned encoder」（而这条在 AHI4 不可用，R3）。此时「可迁移」应降级为「**已内建，无需迁移**」。
- **需要什么对照**：①已知音节边界的 A1；②未知边界（打乱边界 A3）——两者之差就是「免费对齐」的价值；若差≈0，说明对齐在本载体上无价值。

### R7 规模方向相反：LST 的增益随规模增长，AHI4 是玩具级且无梯度

- **主张**：LST 在 420M→1.8B→7B 上增益持续/放大，所以机制「越用越值」。
- **最可能错在哪**：增益随规模放大恰恰说明它是**规模耦合**机制 `[文献]`（§5.2 第 7–8 页；Figure 4）。AHI4 的 D=256 玩具级、无反向传播、8 个原语（AGENTS 诚实边界），在这个尺度上要么测不出、要么测出的是别的东西（例如手工特征先验）。
- **如何证伪**：本探针若在 21 音节/3 种子上测不出稳定增益，**不能**写「规模大会好」；只能写「本载体未测出」。反之，若测出，也只对本仓尺度的 5 类任务成立，不得外推到「语音理解」。
- **需要什么对照**：本仓没有可比的规模轴（无 420M/1.8B），所以**这条永远只能标「未测」**，这正是把「可迁移」写成条件句的理由。

### R8 「判据 PASS」可能只是任务太简单（0.857 已逼近上限）

- **主张**：皮层留一音节可分度 0.857（chance 0.2）已证明表征好；patch 聚合会更好。
- **最可能错在哪**：0.857 是**5 类**任务（声母方式：不送气塞/送气塞/擦/塞擦/鼻边），21 音节×3 种子，留一音节 `[实测]`（`判据_发音_v9.json` G2 臂；`皮层_音素格.跑`）。5 类且类别强可分时，多数臂都会 >0.8 ⇒ **没有分辨率**看 A2 vs A1 的差异。另外 0.857 与 1.0 之间的余量只有 9 个测试项，`[推导]`。
- **如何证伪**：若 A2/A1/A0 三者都 ≥0.85，则本任务判「无分辨率」，主结论无效，必须换 21 类音节身份（chance 0.0476）重跑（预注册为 P7 副指标，阈值 2×chance）。
- **需要什么对照**：①21 类难度控制臂；②混淆矩阵（看是否只靠 1–2 个粗特征）；③随机标签 must-fail（A6）。

### 1.9 对 E2/E3 到件的交叉核对（E1 未到件）

**分歧 1（最重要）· E3 把「确定性聚合」类比成 LST 的 Static Patching，低估了差距。**

### 3.2 处理（确定性，无训练）

1. 波形 → `耳._分帧` → 逐帧 5 维；`耳.切段` → 段列（类, 起, 止）。
2. **单元定义**（各臂不同，见 §3.3）：每个单元取 `s_j = [mean5, std5, onehot(类)3, log1p(ms/10)]`（共 14 维；单帧单元 std=0）。
3. **编码**：冻结随机符号投影 `P ∈ {−1,+1}^{D×14}`（种子 65001，D=1024），`u_j = 归一(P s_j)`（`能力核.归`）。**无学习、无外部权重**；投影种子与数据无关。
4. **样本描述子**（所有臂同式，保证只有粒度不同）：`d = concat(mean_j u_j, std_j u_j, u_first, u_last) ∈ R^{4D}`。
5. **读出**：每类原型 `w_c = 归一(叠_c d)`；`读(码本, d, k=1)` 最近原型；同折训练、留出测试。
6. 指标：LOSO 准确率（主）、21 类准确率（副）、压缩比＝平均单元数/平均帧数、cosine silhouette（报告用）、静音折叠节省单元数。
7. 确定性：整轮跑两遍（两个进程），JSON sha256 必须逐位同；异种子（310 vs 311）描述子 sha256 必须不同。

### 3.6 FAIL 即撤回（硬条件，逐条写）

1. **P1 失败** ⇒ 撤回「patch 级单位优于音节/帧级」与「LST 机制在本载体可迁移」两条主张；结论改「本载体不成立」，且不得用「规模/数据不足」解释（那是未测，不是理由）。
2. **P2 或 P3 失败**（打乱臂没塌）⇒ 撤回「有界上下文/边界结构携带信息」；登记为「统计聚合收益来自全局池化，不是 LST 的机制」。
3. **P5 失败** ⇒ 整轮作废（读数不可用），修 readout 后用**新音节/新种子**重跑；旧数据不得复用。
4. **P4 失败**（准确率过但压不下来）⇒ 只撤回「省算力」，保留「单位粒度可分」；反之（压下来但准确率不过）⇒ 只保留「可压缩」，撤回「不损可分性」。
5. **P7 失败**（21 类不优于 A1）⇒ 只允许声明「5 类粗任务上成立」，降级为「未证实泛化」。
6. **不得 post-hoc 救**：跑完后出现「A2 不行但 A1 好」时，不得改称「A1 就是 LST patch」来维持「可迁移」——那是 R5 已经预告的映射错误，必须在报告里明写「AHI4 已内建该单位，无需迁移」。

## 7. 结论（给 Lead 的裁决建议）

1. `[提案]` **把「LST 机制可迁移」降级为「单位粒度假设-未证实」**，写入纪要时用条件句：「在本载体上，若确定性分段+统计聚合在 5 类 LOSO 上不优于音节/帧级基线（P1 失败），则不可迁移；该探针尚未运行。」
2. `[提案]` **可迁移成分只保留一句**：「把序列建模单位抬到与文本同尺度」这一**问题意识**。实现的三个前提（learned patch encoder / HuBERT 离散 token / Transformer+预训练）在 AHI4 全部不可用，因此「直接借」不成立，「需改造」也只在探针 PASS 后才成立。
3. `[实测]` **红线其实不需要为「借机制」改**：AHI4 现有链路零外挂（v9 G4 读入 0 / 禁词 0 / 两趟同 true），而「patch 聚合」在 AHI4 的确定性版本不引入任何外部权重。因此 L0 就够；把「变宽松」写成「L1/L2 + 明文登记 + 屏蔽测试」更符合所有者诉求，也保住 C10 的可证伪性。
4. `[提案]` **先探针、后引擎**：探针 FAIL 则撤回「可迁移」，并如实登记「AHI4 已有的音节单位可能已是 LST patch 的正确尺度（R5）」——这是负结果，也是有价值的结论；不得用「规模不够」挽回。
5. `[提案]` 对 E1/E2/E3 到件的交叉核对：本件 §1.9 已对 E2/E3 给出 4 处分歧（E3 的「L0≈Static」高估、E2 的 8–16 上限外推、静音折叠高估、读出侧落点与诉求落差）+ 3 处补强；E1 未到件，到件后按其实际表述补一轮。附录 A 的原文数值是独立抽取的，若与 E1 到件冲突，以「双方给出页码/表号」的方式登记差异，不互相覆盖。
