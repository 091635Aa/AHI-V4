## 0. 五条结论（数字先行）

1. **默认设备走 MME，延迟 90ms；同一硬件换 WASAPI 只要 3ms —— 差 30×。** 实测：`默认 In=1 / Out=4`，两者 `default_low_input/output_latency = 0.09s`、`default_samplerate=44100`（MME）；而 33 个设备里同一 Realtek 硬件在 WASAPI 下：**i=17 麦克风阵列 48000Hz / lat_in 0.003s**、**i=14 扬声器 48000Hz / lat_out 0.003s**。⇒ **实现必须显式指定 `(hostapi=WASAPI, device=17/14, samplerate=48000)`，不准用默认 1/4**，否则 90ms 直接吃掉 VAD 响应预算。
2. **夜里噪声底 = -62.1 dBFS（RMS 0.000783，峰值 0.00485，无削波）**；采集 2.248s 音频墙钟 2.248s（无溢出），`stream.latency=0.032s`。⇒ VAD 门限取 **-52 dBFS（RMS≈0.0025 = 噪声底×3.2）**，起音 2 帧（20ms）、尾音静音 **300ms** 判端点。
3. **原生声带是「3 倍实时」，不是瓶颈**：`FS=16000`；构造 **55.5ms**；6 字合成 **348.1ms / 音频 1.04s（实时率 0.335）**；18 字 **794.1ms / 2.69s（0.295）**；`tracemalloc 峰值 15.25MB`。⇒ **说 1 秒话需 0.30–0.33s 计算**，只需 **提前 0.35s 预合成**即可连续播放；长句按 0.30×时长线性外推。
4. **TTS 兜底冷启动 1.18s 是坑**：`pyttsx3.init()` 实测 **1179.7ms**，rate=200，可用音色 `Huihui zh-CN` / `Zira en-US`。⇒ 兜底必须**常驻预热引擎**（init 只做一次），否则首句 1.2s + 合成时间会破「自然对话」感；且 SAPI 输出**不可控音色参数**，只能当降级。
5. **音色注册 30 秒够用，但相似度天花板要老实说**：8 参数音色模型在 30s（3×10s）下，F0 均值相对 SE ≈**0.57%**、段间 CV ≤15% 可判；录 3s 时 SE 仍 <2%（F0 够稳）——**真正不稳的是气声/紧喉/共振峰**（受麦克风与房间影响）。**存储量 30s×16kHz×2B = 0.96MB；音色档案 <1KB**。**口径：只能做「参数化模仿」（声带 8 参数 + 共振峰缩放），不是真声克隆**，相似度预期上界余弦 **≈0.80**。

## 1. T1 · 听觉输入：设备/窗口/阈值（四件套）

- **主张**：真机听觉链路可在 **25ms 帧 / 10ms 跳** 下稳定跑，端到端「说完→判完」延迟由 **VAD 尾音 300ms 主导**（≈400ms），不是算力瓶颈；采集必须锁 WASAPI 48000 并做 **48k→16k 整数 3:1 抽取**（声带是 16k）。
- **证据**：[实测] 默认 in=1/out=4 均 MME `lat=0.09`；WASAPI i=17 `lat_in=0.003` / i=14 `lat_out=0.003`；mic 实测 RMS **0.000783 / -62.1 dBFS**、peak 0.00485、`stream.latency=0.032`；设备共 33 个、hostapi 4 种（MME/DirectSound/WASAPI/WDM-KS）。特征沿用 `耳朵.py`（F0/能量/7 频带/谱平坦度 ⇒ HDC 声向量）。
- **反证（必须失败对照）**：①**10s 纯静音臂必须 0 次误触发**（若触发 ⇒ 门限太低）；②**白噪声 -45dBFS 臂必须 100% 触发**（若漏 ⇒ 门限太高）；③若实测端到端 >800ms ⇒ 我的「300ms 尾音主导」被推翻（说明特征/读出更贵）。
- **代价**：25ms 帧@16k = 400 采样/帧；HDC D=1024 编码 ≈ 1024 乘加/帧 ⇒ **102,400 乘加/秒**（忽略）；内存 = 1.5s 滑窗 **24KB**（16k×1.5×2B float32=96KB，取单声道）。**VAD 无模型，纯能量+过零率 ⇒ 0 GPU。**

## 2. T2 · 决策→文本→声带→扬声器 执行链（延迟预算，四件套）

- **主张**：链路可行，**最短可感知回应 ≈400ms**（VAD 尾音 300 + 决策 2.4 + 合成 0.35×时长 + 播放 3ms）；若改成「起音即打断式」可压到 **≈150ms**，代价是抢话。
- **证据**：V5 两区室核 **2.435ms/拍**（D=64，meeting54 实测）；声带 **实时率 0.30–0.33**；WASAPI 输出 **3ms**、MME **90ms**；mic 采集 **0.032s**。逐段预算：采集 25ms 帧 + VAD 30ms（起音 2 帧）+ 尾音 300ms + 声纹/情绪读出 ≤5ms + 决策 2.4ms + 合成 0.35×T + 播放 3–90ms。
- **反证**：若 300ms 尾音被判「太慢」（实测用户打断/插话场景），则必须加**交互式 VAD**（首帧即触发、边听边合成），但那会引入「边说边改」的文本回滚 ⇒ 需先测「回滚率 ≤10%」；否则不许改。
- **代价**：单轮 CPU **≤10ms**（不含合成）；内存：滑窗 96KB + 声带 **15.25MB** + 决策核 <42MB ⇒ **<60MB**（CPU 侧）。

## 3. T3 · 情感音色输出：声带 vs TTS，可测差异（四件套）

- **主张**：**主路径用原生 `声带.py`**（16k、3 倍实时、参数完全可控、确定性 wav）；**TTS 只作兜底**（中文可懂度高但**音色/情感参数不可控**、init 1.18s）。情感韵律用 8 参数轴驱动（F0 中位数/跨度、语速、能量、气声、紧喉、声区），**每条都要给可测差值**。
- **证据**：[实测] 声带 6 字 348ms/1.04s、18 字 794ms/2.69s、实时率 0.335/0.295、`tracemalloc 15.25MB`、构造 55.5ms、FS=16000；`pyttsx3.init()` **1179.7ms**、rate 200、音色 Huihui/Zira；声带参数轴见 `meeting38/…/05_情感韵律发声专家.md`。
- **反证（必须失败对照）**：**中性臂 vs 高兴臂**（同文本）必须 F0 中位数差 **≥15% 且语速差 ≥10%**；若「换情感参数但输出波形余弦相似 >0.99」⇒ 参数没生效（装饰）。**模仿臂 must-fail**：用**默认参数**（非本人）合成同一句，相似度必须 **<0.70**，否则相似度指标无分辨力。
- **代价**：合成 0.30–0.33×实时；16k/16bit 单声道 1 秒 = **32KB** ⇒ 30s 语音 960KB；wav FIFO 缓冲 **建议 2s（64KB）**，播放线程独立，避免与合成抢 GIL。

## 4. T4 · 判据/资源/风险：最小可判实验与降级

- **主张**：本轮最小可判集 = **3 个真机实验**（采集/端点、情感差异、音色模仿），总预算 **≤3min**、声卡占用 **≤6s**；**其余全部文件仿真（wav 回放）**，避免夜里占麦。
- **证据**：见上三条；设备/延迟/噪声底均为 [实测]。
- **反证**：若三实验任一 must-fail 不过（静音误触发、情感差 <阈值、默认参数相似度 ≥0.70）⇒ 该项判 **FAIL**，不许用「主观觉得像」代替。
- **代价/降级阶梯**：①声卡打不开（`PortAudioError`）⇒ 降级为 wav 仿真（不影响判据）；②采集丢帧/NULL ⇒ 重试 2 次退到仿真；③合成跟不上播放（欠载）⇒ 预合成 0.35s 提前量；④TTS 兜底 ⇒ 引擎常驻预热；⑤全部失败 ⇒ 只交「离线 wav 判据」，真机标**未测**。

## 5. 音色模仿的数据量与稳定性（本队算账）

| 录音量 | F0 均值相对 SE | 段间 CV（3 段切分） | 判 |
|---|---|---|---|
| 3s | ≈1.8% | 不可切 3 段 | 只够 F0 |
| **10s** | ≈1.0% | 20–30%（气声/紧喉不稳） | 勉强 |
| **30s（3×10s）[推荐]** | **≈0.57%** | **≤15% 可判** | ✅ 注册线 |
| 60s | ≈0.40% | ≤10% | 更好，但收益递减 |

- **判据**：注册取 30s（3 段×10s，不同音量各一）；**段间参数 CV ≤15%** 才接受；**跨会话（换天/换麦）漂移 >20% ⇒ 必须重标定**（否则「知道我的声音」是假的）。存储 0.96MB/人。
- **必须失败对照**：拿**别人的 30s** 注册一个"假档案"，用它合成 ⇔ 与本人相似度必须 **<0.70**（否则声纹/音色分辨力不足）。
- **诚实边界**：**参数化模仿 ≠ 真声克隆**；不主张「复刻所有者声音」；相似度上界约 0.80（余弦），且强依赖录音质量与麦克风（本机为 Realtek 阵列，非录音级）。

## 6. 私有假设

1. **16k 是硬约束**（声带 FS=16000）；若改用 22.05k/44.1k 需重做共振峰系数，本队价码不变。
2. **WASAPI 独占会让其他程序没声音**；夜里可接受，白天需改共享模式（延迟回升到 ~10ms）。
3. **VAD 用能量+过零率**（无模型）；噪声底会随风扇/空调变化，**门限必须每轮重标**（本机当前 -62.1 dBFS，白天可能 -50）。
4. **相似度余弦的上界 0.80** 是 [未验证假设]（未跑）；若实测 0.9+ 则更好，若 <0.6 则「模仿」一词要撤。
5. 本轮**未测**：长时 30min 稳定性、跨会话漂移、真人听感评分、TTS 实际音质。
6. **声卡/声带不是本队独占**：探针期间 `AHI4/meeting32/发声台账.jsonl` 在 **00:28:04–00:28:09** 有别人写入（发声号 35/36「今天过得怎么样？」「我们一起走吧。」），**早于本队 00:29+ 的探针**；本队两次 `发声()` 产出的 wav 落在 `meeting55/黄队/_tmp_声带/`（`发声_000001/000002.wav`，33,324/86,124B）⇒ **本队未写既有目录**。但提示主控：**声带/麦克风存在并发占用风险**，真机实验须串行排队，否则会互相打断。

**大白话**：麦克风和喇叭默认走的是"慢速通道"，一问一答要多等 **90 毫秒**；同一套硬件换成"快速通道"只要 **3 毫秒**，所以代码里必须点名用快通道。夜里很安静（底噪 -62 分贝），只要把"开口"的门限设高一点，就不会把风声当人说话；判断"说完了"要等 0.3 秒安静，所以回话最快约 0.4 秒。我们自己那套发声器**说 1 秒话只要 0.3 秒算**，够快；系统自带语音合成冷启动要 1.2 秒，只能当备胎。**想学我的音色，录 30 秒（分三段）就够估准，但只能学"腔调"，学不出"真人声"**，别对外说"复刻了我的声音"。
