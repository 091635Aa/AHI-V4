## 0. 先立定义：「像人一样看」的可操作定义（本专家推导，不再回头追问所有者）

所有者的三句原话给出的是**否证条件**（"模型识别只能框出来，而不能知道"、"cv2 特征=AI 世界的看"、"OCR 永远不要"），但没有给出**正例**。作为视觉认知科学专家，我把正例推导成一个可判据、可实现的定义：

> **「像人一样看」= 一条受注意调制的、注视限制的采样轨迹。**
> 它每拍的输出是三元组 **(下一注视点 g′, 惊讶/预测误差 s, 保拓扑的视觉场 Φ)**；
> 而**不是**单帧全域解析出的**离散物体列表**。
> 看 = 「带着预测去采样 → 只把"意外"传下去 → 据此决定下一眼看向哪里」。
> 世界稳定时它几乎不输出（视而不见）；世界变化时它把注意与动作引向意外处。

对照地给「AI 式看」的可操作定义：

> **AI 式看 = 单帧全域 → 投影成特征向量 → 与固定类别码本/检测器比对 → 吐离散符号（框/标签/字）列表。**
> 其判据性特征：**有状态≈无**（输出由单帧决定）、**外观驱动**、**输出是世界的符号描述**。

由此得到二者唯一可靠的**划界判据**（贯穿全文、也是失败判据的骨架）：

| 维度 | AI 式看 | 人眼式看 |
|---|---|---|
| 输入范围 | 全帧、均匀分辨率、一次性 | 注视点邻域（中央凹）+ 周边低分场 |
| 时间性 | 每帧重置（无状态或仅做 tracking） | 沿注视轨迹演进，**强状态** |
| 向量用途 | 去**类别码本**里检索最近的符号 | 去和**上一拍的预测**比对得惊讶 |
| 输出形态 | 离散、全局的**框/标签列表** | **注视点 + 惊讶标量 + 保拓扑场** |
| 输出去向 | 世界的**描述** | 下一步的**动作/注意驱动量** |
| 对稳定世界 | 每帧都全量解析（照看不误） | 适应、几乎不输出（视而不见） |

**一句话**：区分二者的不是"是否编码成向量"，而是 **"投影什么 + 投影去干什么 + 输出给谁用"**。

## 1. 人眼视觉计算机制清单 —— 逐条判断可复现性

判定口径：**"能复现"= 只用 `共存态.py` 已有 HDC 原语（特征码/字码/文本码/绑/束/相似/批相似）或对像素做确定性算术后能组合出来，无需训练、无需梯度、无需外挂模型。**

| # | 机制 | 人眼要点 | 纯 HDC 能否复现 | 依据（源码 / 机制） | 工程含义 |
|---|---|---|---|---|---|
| 1 | **中央凹–周边采样** | 仅中央凹 ~2° 高分辨；周边低分但敏于变化/运动 | **能** | `器官_眼._察变`（L126-141）已把全帧压到宽320 求 `absdiff>25` 占比——**把标量扩成分块网格**即得"周边场"；中央凹=绕注视点的小窗 `编码.特征码` | 计算量从"全帧解析"降到"一窗 + 一网格"；纯 CPU 可跑 6Hz |
| 2 | **眼跳 saccade + 注视 fixation（主动采样轨迹）** | 视觉是一串注视，注视间跳跃，不做连续扫 | **能** | 注视点 = 周边场 argmax + 偏置（纯 argmax + 状态机，无模型）；saccade 本就允许跳跃 | 视觉输出从"快照"变成"轨迹"，天然抗"每帧重置"；这正是"像人看"的形式骨架 |
| 3 | **预测编码 / 惊讶响应** | 大脑预测下一输入，只上传预测误差；稳定刺激被"预测掉" | **能（用非训练预测器）** | `编码.相似`（L140-145）：`s = 1 − cos(实际注视码, 预测注视码)`；预测器用**恒常预测**（世界不变）或**移位外推**，无需学习 | 稳定画面惊讶≈0→不投事件、不更新（省算力且"视而不见"）；变化→惊讶峰→驱动注意 |
| 4 | **注意驱动（自下而上显著性 + 自上而下目标）** | 注意=选择器：显著性与任务目标共同决定看向哪 | **能** | 自下而上=变化/对比场（#1）；自上而下=`意图槽.当前`（L185-187）、`动作槽.光标`（L190-192）作偏置——**正是所有者要的"联动式视觉"** | "看"被脑/手调制；手一动，眼自然被拉过去 |
| 5 | **整体优先 / gist（~100ms 场景感）** | 先得粗印象，再局部识别；**gist 不是物体列表** | **能** | 对**降采样整帧**求 `编码.特征码` 得"全局粗场码" | 用于场景切换检测与自上而下先验；**严禁**把 gist 落回框列表，否则退回 AI 式 |
| 6 | **视觉恒常性（大小/颜色/明度）** | 视网膜像变而物体知觉不变，依赖参照系 | **部分** | 位置恒常=用相对/跨帧编码可做；大小恒常需尺度参照（可借 `语义.容器树` 的几何包含）；**严格颜色恒常需光照估计——做不到** | 恒常性靠"跨帧状态（记忆）"而非单帧算法，与 #3 同源；色彩恒常是诚实缺口 |
| 7 | **运动/变化优先（magno 通路）** | 瞬变/运动优先获得加工与注意 | **能** | 低分时间差分（#1 的变化通道），在显著性里高权重 | 移动的光标/动画优先进注视——联动链的物理基础 |
| 8 | **知觉即交互 / affordance（Gibson）** | "是什么"由"能对它做什么"给定 | **能（项目已实现）** | `语义.py.记点击`（L244-295）功能签名 = 点击前后屏幕差分的 HDC 束；`_元素码`（L222-242）名字/长相只作特征不作标签 | **这是"知道"的主路，且零模型**——所有者要的"知道内容"的现成一半 |
| 9 | **双眼 / 深度 / 立体视觉** | 视差→深度，辐辏调节 | **不能** | `器官_眼._截屏`（L120-124）是单屏单眼 mss 截屏，无第二视差源 | 天花板：只有 2D 平面。`语义.容器树`（最小包含者，L95-147）是**层级的近似替代**，但不等于深度知觉 |
| 10 | **连续知觉流 vs 离散物体列表** | 交出去的是**连续、保拓扑的场**；"物体文件"（~4 项）是**下游记忆产物** | **部分**（接口可换；物体文件仍会作为下游产物存在） | 现接口 `元素s=框列表`（共存态.py L178/239-256）正是要被替换的形态；`语义.容器树` 本身即一种"在场关系"结构 | **主接口改为场/注视/惊讶；物体列表降级为"注视确认后涌现的在场者"**（见 §2/§4B） |
| 11 | **适应 / 抑制（对恒定刺激不响应）** | 神经元对持续刺激适应，只传变化 | **能** | 惊讶 < 阈值 → 不投事件、不写更新；`编码.相似` 天然度量"是否变了" | 大幅减少无效写与算力，等价于"稳定元素不重算"的既有约束 |
| 12 | **反馈 / 循环（感知=推断）** | 大量自上而下连接，感知是"预测→比较→纠正" | **部分** | **确定性**反馈（恒常/外推预测→比较→纠正）能复现；**学习到的**反馈需梯度/训练，被 C1 禁止 | 天花板：熟练化（专家"看一眼就懂"）靠经验学习的那部分做不到；只能用确定性预测器 |
| 13 | **时间整合（注视停留 200–300ms 累积）** | 一次注视内积分多帧提高信噪比 | **能** | 注视停留期内对注视码做 `编码.束`（L131-138）多拍整合 | 用时间换精度，契合"连续知觉流"；且天然抗单帧噪声 |
| 14 | **视网膜拓扑组织（retinotopic maps）** | 视皮层保留空间邻接关系，是"场"不是"袋" | **能** | `编码.绑`（L121-129）支持**循环移位的位置绑定**；`束` 各子块 = `特征码(子块) ⊗ 位置码` | **这是"场码"的数据结构基础**：保拓扑、不是框列表。也是回答张力 A 的关键 |
| 15 | **返回抑制 / 扫视抑制（IOR）** | 刚看过的位置短期抑制，避免反复盯 | **能** | 注视历史（deque）对刚访问块降权；纯计数/状态，无模型 | 让扫视不原地打转；是 #2/#4 的稳定器 |

**汇总**：15 条中 **11 条可完整复现**（#1,2,3,4,5,7,8,11,13,14,15），**3 条部分复现**（#6,10,12），**1 条不可复现**（#9 双眼/深度）。**没有任何一条需要 Transformer/OCR/外挂模型或梯度。**

## 2. 具体方案：注视–预测视觉回路 GPV（Gaze-Predictive Vision，纯 HDC 无模型）

> 目标：把 `眼器.一轮` 从「截屏→检测框→识字→写列表」改为「截屏→周边场→眼跳/注视→中央凹采样→预测比对→写 场/注视/惊讶/轨迹」，并让 `元素s` **降级为注视确认后涌现的在场者**（保字段、保签名、向后兼容）。

### 2.1 数据结构（写入 `共存态.视觉槽` 的**新增字段**；眼单写，深拷贝快照，锁内不算）

```
视觉槽新增（不删旧键）:
  # ① 保拓扑的周边场 —— "看见变化在哪"，不做识别
  场: {
    网格: (Gx, Gy) = (16, 9),                 # 每块约 120×120 像素（1080p）
    变化: ndarray(Gx*Gy,),                    # 块级 |帧t − 帧t−1| 灰度均值，[0,1]（#7）
    对比: ndarray(Gx*Gy,),                    # 块内灰度方差（边缘/结构代理），[0,1]
    场码: ndarray(D=1024,),                   # 束_块[ 特征码(块) ⊗ 字码("pos:bx,by") ]（#14）
  }
  # ② 注视状态 —— 看的主体是一条轨迹，不是一张快照
  注视: { 点:(x,y), 块:(bx,by), 停留拍:int, 起t:float }
  惊讶: float,                                 # s_t = 1 − cos(c_t, ĉ_t)（#3）
  扫视轨迹: deque(maxlen=32) of { t, 从:(bx,by), 到:(bx,by),
                                 触发:"变化"/"对比"/"目标", 惊讶:float }   # #2/#15
  # ③ 次级产物：注视确认的"在场者"（object file 由凝视涌现）—— 兼容旧接口
  元素s: list[ { 句柄, 框, 心, 主色, 形状, 字:"", 置信,
                 注视码:c̄, 惊讶:float, 在场拍:int } ]        # 字恒为空（C9）
```

**关键**：`场/注视/惊讶/扫视轨迹` 是**主接口**（像人）；`元素s` 是**派生接口**（旧世界的兼容层），其产生方式不再"全帧检测"，而是"**注视稳定后被动确认**"。

### 2.2 算法步骤（`眼器.一轮`，维持 4–6 Hz）

```
输入: 屏幕帧 x_t；状态: 上帧块灰 blk_{t-1}, 上注视, 上注视码 c_{t-1}, 注视持久度
输出: 写下 场/注视/惊讶/扫视轨迹；元素s=在场者（若确认）

1) 截屏 x_t（复用 _截屏, L120-124）；降采样到 16×9 网格，取每块灰度均值与 RGB 均值。
2) 变化[blk] = |blk_t − blk_{t-1}|；对比[blk] = 块内灰度方差。        # 复用 _察变 思想(L126-141)
3) 自上而下偏置 bias[blk]：动作槽.光标 / 意图槽.当前目标所在块 +2；最近注视块 −1（返回抑制 #15）。
4) 显著性 S = 0.5·变化 + 0.3·对比 + bias，逐块归一化。                # #4（纯算术+argmax）
5) 眼跳判定：若 注视.停留拍 < K(=2) → 维持注视（继续积分）；否则
   g* = argmax S（排除当前块）→ 更新 注视=(g*,块,停留拍=0)，追加 扫视轨迹。   # #2
6) 中央凹采样：以 g* 为中心取窗（中心 80×80 高分 + 外围 160×160 低分，多尺度）。  # #1
7) 注视码 c_t = 束_{子块}[ 绑( 特征码(子块特征), 字码("pos:%d,%d") ) ]  # #14 保拓扑
   （子块特征 = 块内 (x,y,w,h 相对坐标, RGB 均值)；绑=按位乘, 字码(位置)=位置token）
8) 预测码 ĉ_t：
   · 默认恒常预测 ĉ_t = c_{t-1}（"世界不变"）                        # #3/#12（非训练）
   · 若 手忙(动作槽.状态≠闲) → 用 位绑移位 做注视点外推（预测眼随手动会扫过）
   惊讶 s_t = 1 − cos(c_t, ĉ_t)                                        # 编码.相似 L140-145
9) 时间整合：注视停留期内 c̄ = 束(近 K 拍注视码)。                    # #13
10) 在场确认（object file 涌现）：若 停留拍 ≥ K 且 惊讶均值 ≤ θ(=0.35) → 生成/匹配在场者、
    写入 元素s。跨帧匹配 = 复用手法 `_配句柄`(L192-216) 的贪心，但**匹配键加入 cos(c̄, 旧c̄)**，
    使"同一个东西"由**注视码稳定**而非仅 IoU 定义（更像"看着它没变"）。
11) 写 场/注视/惊讶/扫视轨迹。元素s ← 在场者。                          # 视觉槽写, L239-256
12) 若 s_t > 0.5 → 态.投事件(类="惊讶", 点=g*, 惊讶=s_t)  # 事件槽(L211-213) → 脑/自我线程消费(联动)
```

### 2.3 「知道内容」如何在不分类/不打标签下产生（对接 `语义.py`，见 §4C）

- `语义.py.运行`（L352-364）每拍读 `取视觉().元素s` → `建容器树`（最小包含者）+ `叠加优先级`；**在场者仍在 `元素s` 里，故语义层零改动**。
- `记点击`（L244-295）：手真实点中句柄 → 前后在场者差分 → `功能签名 = 束(新增码⊕消失码)` → `_重聚类`（L298-333）形成 `W1/W2…` 功能词。
- **本方案的两处增益**：
  1. 文字变化项恒为空（禁 OCR），功能签名**完全由"交互后哪些在场者出现/消失"决定**——比现状更纯、更贴 affordance。
  2. 新增的 `惊讶` 提供"初识"能力：**能预测=熟悉；预测失败=有东西（在场但未知）**——这就是人眼式的"知道有个东西"，不含名字。

| 位置 token | `编码.字码` | L88-94 |
| 保拓扑场码（块⊗位置） | `编码.绑`（含循环移位） | L121-129 |

### 3.2 必须新增的原语（新增的是**组织层组合函数**，不是新数学）

1. **周边场生成器** `周边场(img, 上灰网格) -> {变化,对比,场码}` + **注视规划器** `选注视(场, bias, 上注视) -> 块`
   - **为什么非加不可**：现有引擎**没有任何"空间显著性/注意分配"原语**。没有它，"看"便无法决定"看哪里"，只能对全帧做一次投影 → 必然退回 AI 式看。这是"像人"的第一个必要条件。
2. **保拓扑场码编码器** `注视码(窗, 位置token) -> 场码`
   - **为什么非加不可**：现有 `特征码` 是**无序全局投影**（向量→码，**位置信息在 ravel 后丢失**）。要复现"视网膜拓扑组织"，必须用 `绑(·, 位置码)` 的结构化编码。这是"场 vs 框列表"的数据结构分界。
3. **预测器 + 惊讶算子** `预测(上码, 手忙?) -> 预测码` ｜ `惊讶 = 1 − 相似(实际, 预测)`
   - **为什么非加不可**：现有 `相似` 只做"检索"（和码本比），**没有"预测下一拍并算残差"的语义**。而预测编码是人眼式看的核心——它决定"看见变化而非看见全部"。
4. （可选，可不新增）注视历史/返回抑制状态：用 `deque` 即可，无需新原语。

> **诚实说明**：上述 3 个"新原语"**全部由现有算子（特征码/字码/绑/束/相似）组合实现**，引擎**一个数学能力都不缺**。新增的只是**组织层（采样、状态、预测、注意）**。

## 4. 可失败判据（≥3；附量化门槛）★含「像人看 vs AI 式看」对照

> 判据必须能**真失败**。以下每条给出"失败即方案作废"的量化红线。回放固定帧序列、固定种子（C13）。

**判据 1（对照·核心）— 单帧决定性检验：输出必须依赖历史/注视状态，而非单帧。**
对**同一帧 x** 注入两种不同历史：`h1`（上一拍注视在左、惊讶低）与 `h2`（上一拍注视在右、惊讶高）。
- 要求：下一注视点 `|g*(h1) − g*(h2)| ≥ 0.25 × 屏宽`，或 `cos(场码_h1, 场码_h2) ≤ 0.8`。
- **失败条件**：两历史输出差异 < 门槛（输出≈单帧决定）→ **判定为 AI 式看，方案作废**。
- 说明：这是"看是否含注视状态"的硬判据；退回全帧投影者，必失败。

**判据 2（对照·响应方式）— 变化优先 + 适应（全局 vs 局部的区别对待）。**
- 场景 A：屏幕**整体**明度渐变 Δ（可预测的全局变化）；
- 场景 B：**局部**移动一个小物体。
- 要求：A 下 `惊讶均值 ≤ 0.2` 且 注视跳数 `≤ 1 次/秒`；B 下 `惊讶峰 ≥ 0.5` 且 1 拍内注视落到移动块，命中率 `≥ 0.8`。
- **失败条件**：A、B 响应无显著差别（都被"全帧变化率"触发）→ 未复现"变化优先/适应"，**判失败**。
- 说明：AI 式看对全局渐变也全帧响应；人眼/预测编码对可预测的全局变化适应。

**判据 3（对照·接口形态）— 不依赖"物体列表"。**
- 要求：在 `len(元素s)==0`（无任何在场者被确认）时，`惊讶` 与 `注视.点` 仍在更新且非平凡（`惊讶` 序列方差 `> 0.01`），且 `扫视轨迹` 持续增长。
- **失败条件**：惊讶/注视 必须等 `元素s` 非空才有意义（"看"依赖物体列表）→ **仍是列表驱动，判失败**。
- 说明：此条直接检验张力 B 的接口是否真的换掉了。

**判据 4（"知道"·不含标签）— 功能同/异只能由交互区分。**
- 复用 `语义.py` 自检情景（L404-434）：外观不同但功能相同的一对按钮 → 交互后**功能词相同**；同名（或同外观）功能不同的一对 → **功能词不同**。
- 要求：`异效签名余弦 < 0.55`、`同效签名余弦 ≥ 0.55`；且系统内**不存在任何人类可读类别标签**（`元素s[*].字` 全空、词表仅 `W*`）。
- **失败条件**：区分依赖 `字`/标签，或聚类无法分开/归并 → **判失败**（且违反 C9）。

**判据 5（联动式视觉）— 自上而下注意调制必须存在。**
- 要求：手移动到点 P 时，注视点在 `≥60%` 的情况下于 2 拍内偏向 P 邻域（对照无手移动基线）。
- **失败条件**：手移动对注视无影响 → 未实现自上而下注意 → **判失败**（也就不是所有者要的"联动式视觉"）。

**判据 6（确定性 C13）— 可复现。**
- 要求：同种子、同固定帧序列，两次运行的 `扫视轨迹 / 惊讶序列 / 场码` **逐位一致**。
- **失败条件**：含未固定随机或调度依赖导致差异 → 判失败（注视抖动如需随机，必须固定种子）。

## 5. 诚实边界（做不到的部分与天花板）

1. **深度/立体：做不到。** 单屏单眼截屏无第二视差源（`_截屏` L120-124）。`语义.容器树`（最小包含者）是层级近似，**不是深度知觉**。
2. **学习性预测：做不到。** C1 禁梯度 → 预测器只能用**确定性**的恒常/外推，无法通过经验变得"熟练"。人眼"专家一眼就懂"的那种加速，本引擎无法获得。
3. **严格颜色恒常：做不到。** 无光照估计模型；只能靠跨帧相对比较缓解。
4. **高级视错觉 / 模糊填充 / 盲点补全：做不到。** 那是学习性反馈回路（#12）的产物。
5. **"命名性知道"：做不到。** GPV 能"知道能做什么（affordance）+ 是否熟悉（惊讶）"，但给不出"这是登录按钮/这是保存页"这种**语言符号命名**——除非未来有语言符号来源。所有者要的"知道内容"，本方案交付的是其**可操作子集**：**知道 = 能被预测 + 能被驱动交互**。
6. **天花板一句话**：**能做"注视驱动的变化感知 + 交互式功能知道"；不能做"无交互的语义命名"。** 冷启动时"不认识的东西"就是不认识（惊讶=max）——这既诚实，也恰是婴儿式的"像人"。

## 6. 对三个核心张力的明确表态

### 张力 A（范式）——`编码器.特征码`（投影成向量再算相似）本身是不是 AI 式看？
**明确表态：不是。向量范式可以保留；要动的不是编码层，是感知的组织层。**

- 人脑确实是神经元群群编码（高维、分布式、双极/稀疏），与 `特征码` 同构；**"编码成高维向量"不是 AI 式看的标志**。
- **可判据的划界**（三条，缺一不可）：
  1. **投影什么**：AI 式投影**整帧**（位置信息在 ravel 中丢失）；人眼式投影**注视限制的小窗/保拓扑场**（块⊗位置）。
  2. **投影去干什么**：AI 式拿去和**固定类别码本**比相似（检索符号）；人眼式拿去和**上一拍预测**比相似（得惊讶残差）。
  3. **输出给谁用**：AI 式输出是**世界的符号描述**（列表）；人眼式输出是**下一步动作/注意的驱动量**。
- 因此分界线 = **"单帧全域 → 与类别码本比对 → 吐离散列表（无状态、外观驱动、输出为描述）" vs "注视限制采样 → 与上一拍预测比对 → 吐惊讶+下一注视（强状态、变化驱动、输出为行动）"**。
- 结论：`特征码` 原语**不动**；新增的 `周边场生成器 / 保拓扑场码 / 预测器+惊讶` 三层组织（§3.2）就是把范式从前者翻到后者的**唯一必要改造**。

### 张力 B（接口）——「元素s = 框列表（离散、全帧、静态快照）」这个接口本身是不是要否的 AI 式看？
**明确表态：是。这个接口形态本身就是要否的 AI 式看的一部分**——它与模型无关：强制"每帧全域解析 → 离散符号"的范式。
- 人眼交给大脑的是**连续、保拓扑的视觉场 + 注视轨迹 + 惊讶**；**"物体列表"是下游记忆产物（object files，~4 项），不是感知接口**。
- **改法：加法，不删**（保 C14 不破既有）。新增 `场/注视/惊讶/扫视轨迹` 为**主接口**；`元素s` **保留名字与全部字段**，但语义改为"**注视确认后涌现的在场者**"（由凝视产生物体恒常，而非全帧检测）。
- **谁写谁读**：`眼` 写全部；`脑.取视觉` 读 `元素s`（不变）+ 新增读 `场/惊讶`；`手.找元素` 读 `元素s`（**不变**，L266-274）；`语义.运行` 读 `元素s`（**不变**，L352-364）；`嘴` 不受影响；`我器` 消费 `事件槽` 的"惊讶"事件（L98-104）。
- **七路如何不被破**：**只增字段、只改 `眼器.一轮` 的内部产生逻辑**，所有既有读方法签名与 `元素s` 的结构不动；`生命体.py` 装配（L28-65）无需改。因此 A1–A13/W1–W6 均可复跑。

### 张力 C（"知道"）——不做分类/不打标签，"知道内容"如何产生？
**明确表态：`语义.py` 的功能签名（=亲历交互结果，名字长相都不参与）已是答案的一半，而且是关键的一半；但不够，需补两块，且要重新定义"知道"。**

- **已有的一半**：`记点击`（L244-295）+ `_重聚类`（L298-333）给出一条**零模型、零标签**的"知道"真值来源——**知道 = 它被交互后世界会怎么变**。这正是 Gibson 的 affordance。所有者"要知道内容"的方向与它一致。
- **缺的第一块（供给）**：它现在吃的是 **YOLO 框**。改吃"**注视确认的在场者**"后，喂给它的才是人眼式的、注意力选出的在场者（§2.2 步骤 10、§4B）。
- **缺的第二块（感知侧初识）**：没交互过的怎么"知道其存在/边界"？答案 = **预测编码的惊讶**（判据 2/3）：**能预测=熟悉；预测失败=有东西（在场但未知）**。这就是"知道有个东西"而无名字，正是人眼的"知道"。
- **可选第三块（类比迁移）**：新区块注视码与某已知功能签名注视码 `cos ≥ 阈值` → 迁移 affordance **假设**，但状态记为"未知"，直到真实点击裁决（照抄 `语义.py` 叠加支配 L150-184 的"**未裁决=未知**"模式）。仍然不打标签——"词"是 HDC 聚类涌现的代号 `W1/W2`，非我们赋予的语义标签。
- **结论（"知道"的可操作定义）**：**知道 = 能被预测（惊讶低=熟悉） + 能被驱动交互（功能签名=能做什么）**。两者**全部用现有 HDC 原语、零分类、零标签**。这交付了所有者所要"知道内容"的**可实现子集**；其上限见 §5.5（不给命名性语义）。
