# meeting38 五专家会议 · 三号专家 · 语言表达（思考—表达分层 / 计划性自我陈述）

> 定位：本席是「大语言模型专家的对立面」。**禁用 Transformer**：无 attention / QKV / softmax /
> 自注意力 / 位置编码 / 生成式 LLM。语言表面 = **HDC 码本 + 检索 + 模板组合**。
> 只做设计，不改任何既有文件；本文所引代码均为 meeting28/31/32/38 既有资产（函数名级）。
>
> 病灶（所有者原话）：「他说话不要他妈把日志倒下来」。现状 `器官_脑.py::_发声()` 输出的是
> 「我在想：眼前 %d 件东西，碰熟了 %d 个，认识了 %d 类功能」——**遥测数字堆砌 = 日志体 = 不是说话**。
> 所有者要的对外语言是**计划性自我陈述**：「我想着…我应该干什么？我这一步要干什么？我还要干什么？」
> 且**思考（内部）与正文（对外）分层**，并让语言与声音成为一体（原声声带输出）。

---

## 0. 一句话裁定

**在既有的 `脑器._发声()` 处切开两层**：脑的**内部思考**写进「自言空间」（六类、带账本引用、
可审计、用户可查、**永不朗读**）；对外**只允许「计划句」**进表达槽，由**模板骨架 + HDC 检索填充 +
状态条件化 + 计数语言模型仅提供连接词**合成短句，再由 `声带.发声(向量, 文本, 遥测)` 原声输出。
绝不重写语言内核——把 `inner_speech`/`lang_codec`/`gen_lm`/`dialogue_v2/v4/v5`/`声带` 的既有函数**搬用**。

## 1. 思考层 vs 表达层：数据结构与职责

### 1.1 总览（两流一闸）

```
状态快照(态) ─┬─► 思考层：言语器.想()  ──► 自言空间(六类, 内部, 可查, 不朗读)
              │                              │
              │                              └─(投影/引用)─┐
              └─► 表达层：言语器.表达计划()  ◄──────────────┘
                                   │
                                   ▼  硬闸：类型必须 == "计划句"
                            表达槽.排队说(条目)  ──►  嘴器.运行()  ──► 声带.发声()  → 声音
```

- **思考层**：职责 = 记账、归因、自省、计划推理。允许长句、允许遥测数字、允许犹豫与自我打脸。
  存储 = `inner_speech.自言空间`（六类：疑问/假设/预测/复盘/计划/自评；每条强制 ≥1 账本引用；
  `审计()` 独立核对）。**默认可见性 = 内部**，用户可经查询接口查看，**嘴不读**。
- **表达层**：职责 = 把当前意图/计划/进度**投影成 1–2 句中文短句**说给外部（所有者）听。
  存储 = `共存态.表达槽`（既有），但**条目升级为结构化 dict**，且只收 `类型=="计划句"`。
- **分层闸**：`脑._发声()` 不再直接 `态.排队说(日志字符串)`，而是先写思考条目，再（可选）投影一句计划。
  表达槽的 `排队说` 侧加校验：非计划句直接拒绝（见 §4 开关接口）。

### 1.2 Schema A —— 思考条目（内部，落入「自言空间」）

复用 `inner_speech.自言空间.追加(拍, 类型, 文本, 触发源, 引用)` 的既有规格，字段语义如下：

```
思考条目 = {
  "号":       int,            # 自言空间自增（查询/审计主键）
  "拍":       int,            # 脑的 思维拍（时间锚）
  "类型":     str,            # ∈ 六类 {疑问,假设,预测,复盘,计划,自评}（inner_speech.自言类型）
  "文本":     str,            # 内部长句，可含遥测数字/自查细节（用户可查，绝不朗读）
  "触发源":   (str, str),     # ("内生"|"外部", 说明)；如 ("内生","块边界调度")
  "引用":     [(int,str),..], # ≥1：(账本号, 原文前缀≤16字)；供 inner_speech.审计
  "支撑意图版本": int|None,    # 该思考所依据的 意图槽["版本"]（可追溯"想的是哪一版计划"）
  "可见性":   "内部"          # 结构常量：思考层恒不对外
}
```

- **只追加、不改动**：与 `inner_speech` 同律（`流: list` 只 append；审计假定「摘录前缀恒定成立」）。
- **账本引用适配**：meeting38 的台账是 `AHI躯体.台账`（`生命体.py` 里 `账.记(类, **rec)`）。
  `inner_speech.审计()` 需要的是 `账本: list[(类型,文本)]`。因此言语器**并行维护一份只追加镜像
  `账本镜像: list[(类型,文本)]`**（每次写台账时同步 append），引用号 = 该镜像下标。
  这是**唯一的集成补丁**，不改台账实现。
- **六类生成不许用关键词路由**（继承 `synthesis.py` 纪律）：类型由**状态量→候选→裁决**决定
  （覆盖缺口→疑问；有预测待检→预测；检验返回→复盘；块边界→计划；周期→自评；猜想稳定→假设），
  多候选时用引擎/计数裁决。**没有任何「词→类型」映射表。**

### 1.3 Schema B —— 表达条目（对外，落入「表达槽」，唯一被朗读者）

```
表达条目 = {
  "号":       int,           # 表达层自增
  "拍":       int, "t": float,
  "类型":     "计划句",       # 硬约束：表达槽仅此一类
  "句":       str,           # 4–24 字，1–2 短句，以「。」收束（不通顺即拒，见判据J6）
  "骨架id":   str,           # 来自哪个模板骨架 P1..P6（可审计"用了哪条骨架"）
  "填充": {                   # 每个槽位的来源与取值（可审计：哪些是检索、哪些是状态）
     "行为":   str,           # 意图.键/滚动 → 动作词（结构常量映射，非路由）
     "对象":   str,           # 检索得到：OCR字 / 语义功能词 / 代词（三选一）
     "对象源": str,           # ∈ {"OCR字","功能词","代词"}（判据J3用）
     "进度":   str,           # 这一步/下一步/还差N步（由动作槽进度+目标栈算）
     "连接":   str|None,      # gen_lm 采样的连接/语气词（可空）
     "语气":   str            # 由遥测(能量e/新异ñ/消化债)条件化选词族
  },
  "意图版本": int,            # 生成时刻 态.取意图()["版本"]
  "句柄":     str|None,       # 被点名对象的句柄（一致性判据J3主键）
  "支撑思考号": [int,...],     # 投影来源的思考条目号（对外语句可溯源自言）
  "声音":     dict|None       # 声带.韵律(遥测) 的结果（基频/语速/幅度…），供原声朗读
}
```

### 1.4 职责边界（谁写谁读）

| 层 | 写入者 | 存储 | 读取者 | 允许内容 | 是否朗读 |
|---|---|---|---|---|---|
| 思考层 | 言语器.想() | 自言空间 | 用户查询 / 言语器自身 | 长句、遥测数字、六类、带引用 | **否** |
| 表达层 | 言语器.表达计划() | 共存态.表达槽 | 嘴器.运行() | 仅 `计划句`、短句、无遥测堆砌 | **是** |
| 声音 | 嘴器→声带 | wav FIFO（`声带.py`） | 耳（自我听觉反馈） | 由向量+遥测驱动的韵律 | 是 |

> 与既有架构一致：脑仍是唯一写表达槽者（`共存态` 文档头「表达槽 ← 脑写，嘴读」），
> 嘴仍**只读不生成**（`器官_嘴.py` 边界声明不变）。本设计只改**脑写出去的内容形态**。

## 2. 「计划性自我陈述」的生成规则

### 2.1 输入的成分抽取（从状态快照取"计划语料"）

`态` 提供的结构化成分（全部来自既有槽位，**不新增语义解析**）：

| 成分 | 来源（既有字段） | 作用 |
|---|---|---|
| 当前意图 | `态.取意图()["当前"]`：含 `句柄/目标点/键/滚动/兜底` | 决定「做什么」 |
| 意图版本 | `态.取意图()["版本"]` | 一致性/防复读锚点 |
| 焦点元素 | `态.取视觉()["元素s"]` 中 `句柄==意图["句柄"]` 的元素 | 取 `字`(OCR)、`框` |
| 功能词 | `态.取语义()`：`按钮s[句柄]["功能词"]` / `词表` | 对象的语义称呼 |
| 手状态/进度 | `态.取动作()`：`状态/进度/目标/句柄/动作计数` | 「这一步/还差几步」 |
| 目标栈 | `态.取意图()["目标栈"]` | 「还剩几件事」 |
| 遥测 | `脑.统计()`：`已碰元素/总尝试/最近结果`；引擎 `e/ñ/消化债/饱足` | 语气、连接词、长度 |

**意图字段 → 动作词（结构常量映射，非关键词路由）**：

```
键 "左"→"碰"，"右"→"点"，"中"→"按"；滚动≠0→"翻/滚"；无意图→"等/看"
```

同义族（变化源之一）：碰∈{碰,戳,按一下,试它}；点∈{点,按,按下}；翻∈{翻,往下翻,滚一屏}。

### 2.2 模板骨架（句法） + HDC 检索（填充）

**分工铁律**：**骨架锁句法、检索填实词、状态定语气**。
绝不用 `gen_lm.生成()` 直接吐整句计划（字符自回归吐不出强约束短句，会把「保存」吐成怪词）。
`gen_lm` 只负责**连接词/语气词**这一小段可空成分。

**六个骨架（P1–P6）**：

```
P1  「我要{行为}{对象}。」                    —— 当前步（面向意图）
P2  「这一步先{行为}{对象}。」                —— 当前步（含顺序）
P3  「{连接}，{行为}{对象}——{对象}像是能{功能}。」 —— 当前步+理由（对象源=功能词时）
P4  「{对象}我{行为}过了，下一步换一个。」      —— 复盘式推进（已试≥1）
P5  「还差{进度}就{阶段}。」                  —— 剩余步（面向目标栈/进度）
P6  「{语气}我在想，接下来{行为}{对象}。」      —— 自评+计划（内部计划外化）
```

**哪些成分是检索、哪些是模板**：

| 槽位 | 机制 | 具体做法（复用函数级） |
|---|---|---|
| 骨架选择 | **状态条件化**（非随机） | 见 §2.3 条件表 |
| `{行为}` | 常量映射 + 同义轮换 | 意图.键/滚动 → 词族；`rng=(种子,拍)` 选同义词 |
| `{对象}` | **HDC 检索** | 三候选：`OCR字`(≤6字) / `功能词` / 代词「这个东西」；用 `编码.文本码(候选)` 与「焦点功能签名」(语义.按钮s) 做 `编码.相似/批相似`，取最高者 |
| `{功能}` | **HDC 检索** | 对 `语义.词表` 各功能词的 `词.码` 做 `编码.批相似(焦点功能签名, 码表)` 取 top1 |
| `{进度}` | 状态计算 | `手.进度`/`已碰元素`/目标栈长 → 「这一步/下一步/还差N步」 |
| `{连接}` | **计数生成** | `gen_lm.生成(种子=语气词, 温度=τ, 最大长=6)` + `dialogue_v5._引号外文本` + 经验谓词守卫 |
| `{语气}` | 遥测条件化 | e高→「我这就」，e低→「我慢慢」，ñ高→「有个新东西」 |

### 2.3 状态条件化（防死板的核心之一）

| 条件（态） | 选骨架 | 行为词族 | 语气 | 说明 |
|---|---|---|---|---|
| 有当前意图、首次 | P1/P2 | 同义族随机 | 中性 | 说"要干什么" |
| 有当前意图、该对象已试≥1 | P4 | "再" | 中性 | 说"这个碰过了" |
| 无当前意图、有目标栈 | P5 | — | — | 说"还要干什么" |
| 手忙（`手忙()==True`） | P2/P5 | — | 「我先」 | 说计划而非打断 |
| 语义有功能词命中 | P3 | — | — | 说"它像能…" |
| e/ñ 高 | P6 | — | 「我这就」 | 兴奋态外化 |
| 消化债高 | P5 | — | 「不急」 | 内压态（复用 `synthesis` 债语义） |

### 2.4 避免退化成死板模板 —— 四个真变化源

1. **HDC 相似检索**：`{对象}`/`{功能}` 由当前功能签名在码表上的 `批相似` 决定，
   状态一变（不同按钮/不同点击结果）称呼就变；不是查表固定词。
2. **状态条件化**：骨架/语气由意图与遥测决定（§2.3），微观状态连续变化 → 句面变化。
3. **rng=(种子, 拍) 同义轮换**：同义骨架/同义行为词用确定性 rng 选（与 `gen_lm.生成`、
   `dialogue_v4.生成连接` 同款 `np.random.default_rng((seed,拍,...))` 惯例），
   同状态复现、异状态不同；**不是每拍复读同一句**。
4. **gen_lm 连接/语气词**：`{连接}` 由计数 LM 采样（温度=引擎 `ñ`），提供自然起句。

> 变体空间 ≈ Σ(骨架 6 × 行为同义 3 × 对象 3 × 语气 3) ≈ 数百种，足以在长跑中不复读。
> **但必须承认**：这是**组合多样性**，不是**生成式理解**（见 §6）。

### 2.5 投影规则（思考 → 计划句）

- **投影仅取一层**：`表达计划()` 读「最近的计划类思考条目」（`类型=="计划"` 且 `支撑意图版本` 最新）
  + 当前意图槽，合成表达条目；**不把思考原文搬出去**（内部长句/数字留在内部）。
- **可追溯**：表达条目 `支撑思考号` 记录来源；用户问"你为什么这么说"时，
  经 `synthesis._溯源报告` 口径回引（自言号 + 账本号）。
- **节流**：沿用 `脑._发声` 的「≥8s 才说一次」+ 「有意图变化才说」（意图版本变化事件优先于定时）。

### 3.2 必须改造（改的是调用点，不是内核）

| 改造项 | 现行 | 改造为 | 理由 |
|---|---|---|---|
| **`器官_脑._发声()`** | 拼「眼前 %d 件东西…碰熟了 %d 个」日志字符串 | 调 `言语器.计划(视,听,动,语)`：先 `想()` 写思考，再 `表达计划()` 排队 | **病灶所在**；不改脑的决策逻辑（`_归因/_注意/_出招` 原样） |

| 声道 | 无声道概念 | 计划句走**自声道**：复用 `dialogue_v5` 的 `lm_s(自声道)`；结构上采不到用户独有词 | 沿用 #226 声道分离铁律 |

| `inner_speech` 引用 | 需 `账本: list[(类型,文本)]` | 言语器维护**只追加 `账本镜像`**（同步台账写入） | meeting38 台账接口不同；最小适配 |

### 3.3 关键词路由红线（继承 #229 / #228）

- **类型选择、骨架选择、对象选择**：一律由**状态量/HDC 相似度/计数**裁决，**禁止** `if "保存" in q`
  这类词→语义映射。
- **唯一允许的"词表"**：动作词/骨架/同义族的**表层形态词表**（surface lexicon，用于构句），
  它**不参与任何决策路由**，只参与"把已定角色说出来"。此点必须在实现里注释声明，接受审查。

## 4. 「正文/思考」分层的开关接口

### 4.1 组装形态

在 `生命体.__init__` 中新增一路语言器（**不改五路边界**，语言器可挂在脑内，也可独立线程）：

```
言语器(态, 台账, 种子=3801, 出声=True, 思考可查=True, 对外计划=True)
```

### 4.2 对外/内部开关（硬闸）

```python
class 言语器:
    # ── 唯一对外出口（硬闸：类型必须 == "计划句"） ──
    def 表达计划(self) -> dict | None:      # 意图/进度/焦点 → 表达条目；无新意→None
    def 排队(self, 条目: dict):             # 若 类型!=="计划句" → 丢弃并记台账(类="言语拦截")
    def 设对外(self, 开: bool):             # False=全静默（演出/冒烟，不扰显示）
    # ── 内部思考（永不朗读） ──
    def 想(self, 类型, 文本, 触发源, 引用号s) -> int:   # → 自言空间.追加
    def 思考可见(self, 开: bool = True):    # 内部流是否暴露给查询接口（默认开）
    def 查思考(self, n=20, 类型=None) -> list:           # = inner_speech.自言流（用户可查）
    # ── 原声 ──
    def 发声(self, 条目: dict) -> dict:      # 坏向量+条目.句+遥测 → 声带.发声()
```

### 4.3 嘴侧改动（最小）

- `嘴器.运行()`：`取下一句()` 得到 `(t, 条目)`；若 `条目` 是 dict，取 `条目["句"]` 与 `条目["声音"]`；
  否则（向后兼容）当作 str 处理。
- `嘴器._发声(条目)`：优先 `声带.发声(...)`；`用语音=False` 或声带不可用 → 打印/写台账（既有降级路径不变）。

### 4.4 分层铁证（供判据）

- **对外队列里永远查不到**：遥测数字堆砌、六类自言的内部长句。
- **内部流里永远查得到**：每条思考的 `引用`（账本号+摘录）与 `支撑意图版本`。
- 两个存储物理分离（`自言自语流` vs `共存态.表达槽`），审计互不污染。

## 5. 可失败判据（5 条，均给出量化口径）

> 判据在**对外输出流**（表达槽消费记录）与**思考流**（自言空间）上分别取样，均可真失败。
> 建议实现为 `言语自检.py`（新文件，可选；不改既有文件），或挂 `自检.py` 的一个新判据组。

### J1 无日志体（遥测数字堆砌）—— 用户明确讨厌项
- **检测**：对每句对外文本跑正则
  `r"眼前\s*\d+\s*件|碰熟了\s*\d+\s*个|认识了\s*\d+\s*类|耳朵刚听着|%\s*\.?\d*\s*f|Hz。"`
- **口径**：命中数 / 对外句数 **必须 = 0**。
- **能真失败的证据**：只要 `脑._发声()` 未被替换（现状），此率 ≈ 1.0 → **必失败**；
  替换后应为 0。这是最硬的回归闸。

### J2 不复读机（重复率上限）
- **检测**：窗口 W=20 句内，句归一化（去数字/标点/连接词）后统计众数占比 `r_top`；
  同时统计相邻两句全等次数 `n_adj`。
- **口径**：`r_top ≤ 0.5` 且 `n_adj ≤ 1`。
- **能真失败的证据**：若关掉 rng 轮换或骨架条件化退化为单一骨架，长跑 `r_top → 1.0` → 失败。

### J3 说的与做的一致（意图一致率）
- **检测**：表达条目带 `意图版本/句柄`；比对**生成时刻** `态.取意图()` 的
  `当前["句柄"]/["键"]` 与条目 `句柄`/`填充["行为"]`。
- **口径**：一致率 ≥ 0.9；且不得出现"说了对象A、意图却是对象B"的跨对象错配。
- **能真失败的证据**：若表达层与意图槽解耦（如用旧快照/滞后一拍且界面已变）→ 一致率跌破 0.9。

### J4 计划性覆盖（当前步/下一步/剩余步）
- **检测**：统计含 ≥3 个动作的窗口内，对外句覆盖 `{当前步(P1/P2/P3), 剩余步(P5), 复盘推进(P4/P6)}`
  的类别数；类别由 `骨架id` 判定。
- **口径**：窗口内覆盖类别数 ≥ 2。
- **能真失败的证据**：若退化成只说"我在碰这个"（永远 P1）→ 覆盖=1 → 失败（不满足"我还要干什么"）。

### J5 内部可审计（引用真实率）
- **检测**：直接调 `inner_speech.审计(账本镜像)`。
- **口径**：`真实率 == 1.0`（违规数=0）；且思考条目数 > 0（不许思考层空转）。
- **能真失败的证据**：任何"引用不存在的账本号 / 摘录不符原文 / 无引用" → 违规>0 → 失败
  （沿用 #242 规格：虚假自言=FAIL）。

### J6（附加）流畅性代理
- **检测**：`gen_lm.三元命中率(句) ≥ 0.5`；句长 4–24 字；以「。」收束。
- **口径**：通过率 ≥ 0.8。
- **能真失败的证据**：若直接上整句字符自回归采样 → 命中率骤降、产出怪词/残句 → 失败。

## 6. 诚实边界（必须如实登记）

1. **语言表面 = 检索 + 模板组合，不是生成式理解。** 计划句的句法由 6 条骨架锁定，
   实词由 HDC 相似检索填槽，连接词由计数 LM 提供。它**不懂**"保存"是什么意思——
   它只是把「当前点击的功能签名」检索到「语义层聚出来的功能词」，再套进句子。
2. **组合多样性 ≠ 语义创造性。** §2.4 的四个变化源能避免复读与死板，但产出的句子在
   语义上仍是**有限槽位的枚举**；不能承诺"任意新意"。
3. **一致性判据只能验"说的与此刻意图相符"，不能验"说得好不好"。** J3 是结构对齐，
   不是语用恰当；句子的自然度只由 J6 的字符三元命中率代理，**非人耳测评**。
4. **未解决项**：
   - 同义/近义（"宠物↔猫"）仍受 #221 字符集重叠局限（`dialogue_v2` 文档已自认）；
     本设计不声称解决语义同义。
   - `inner_speech` 与 meeting38 台账的引用适配靠**只追加镜像**，若台账有删除/覆盖语义
     则镜像会漂移（当前台账为只追加，成立；未来若变需重审）。
   - `声带.py` 的音素/韵律参数为工程近似，**"原声"指管线一体，不指达到真人音质**。
5. **不引入 LLM 的承诺**：全链路无 attention/QKV/softmax/Transformer；
   严禁为"更自然"而引入任何预训练语言模型或神经 TTS。若未来要更自然，
   只在 HDC 码本/骨架库/检索口径上做加法。
