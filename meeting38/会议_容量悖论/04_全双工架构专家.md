# 04 · 认知架构·全双工专家 —— 破「先想再说」：HDC 下的增量式并发语言产生

> 议题：HDC「容量-延迟悖论」。
> 我的锚定：**反对"先想再说"的串行范式**。
> 唯一问题：**人说话不是先成句再说——全双工（边想边说边做）在 HDC 架构下如何实现？
> 意图／内容／韵律如何并行增量生成而不互相打架、且不炸容量？**
> 日期：2026-10-05 ｜ 纪律：只做设计，不改任何既有文件；不碰 Transformer；不提"先想完整句再发声"。

## 0. 一句话主张（先给结论，再论证）

**全双工 = 一条"五级局部小状态流水线" + 一道不可逆的"提交栅栏"（commit fence）。**
容量不靠一个大向量硬扛，而靠**每一级只持有自己那一小窗**——大脑不是"一个全局大向量"，
是**一组各管一小段的局部寄存器**在时间上错位地滑移。

三条被同时封死的逃逸方向，恰好**逼出**这个结构：
- C4（禁线性扩维）→ 不许把 1024 扩成一个能装下全部的大向量；
- C5（禁串行"先想后说"）→ 不许分时；
- C1/C2/C3（禁外挂模型）→ 不许把整合推给外部。
**在三维封死下，"流水线局部化"不是可选优化，而是唯一可行解。**

## 1. 现状诊断：为什么现有实现其实仍是"先想后说"的串行变体

先读证据，不臆测。现有 `meeting38` 的实现已经把眼／耳／脑／手／嘴装成六条并发线程
（`生命体.py:52-98`），W1 也证了"手忙脑不停、嘴照说"（`生命体.py:165-169`）。
**"并发"这一步已经做到了。但"增量"这一步没有。** 逐条看：

| 现状事实 | 位置 | 为什么它还违背 C5 的精神 |
|---|---|---|
| 脑一次 `%` 格式化吐出**整句**，再 `排队说` | `器官_脑.py:186-198` | 从"想"到"说"之间，句子的**全部内容在同一拍内成型**；说只是被推迟到线程里，规划本身仍是整句原子 |
| 表达槽是**整句队列** `deque(maxlen=32)`，`取下一句` 一次取整句 | `共存态.py:194-196, 330-334` | 槽的语义粒度=句；没有"句内中间态"，没有任何可中途修订的窗口 |
| 嘴只做"整句翻译"：SAPI 同步 `Speak(文本)` 整句 | `器官_嘴.py:148-166, 176-183` | 发声是整句不可分割的；一旦开口，句内无法改 |
| 声带 `音节帧()` 一次性 `lazy_pinyin(整文本)`；`合成波形()` 对**整句**逐样本 Python 循环（3s≈48000 迭代） | `meeting32/声带.py:249, 365, 406-468` | 合成是**整段批处理**，没有"推一帧、改一帧"的流式入口 |

**结论**：现有架构是"整句入队 → 整句发声"，
并发只是让**不同整句**在时间上重叠，而不是让**同一句话内部**增量生成。
从"意图产生"到"第一个音"之间，仍要等整句规划完成——这正是所有者说的
**"先想，再说出口"**，只是用线程把它包装得像并行。C5 未被真正满足。

> 所有者的原话必须逐字正视："**想象机之类的，这个也不对，因为还是有延迟性，我们还不能这样子：
> 先想，再说出口。**" —— 他要的不是"更快的整句"，而是**取消"整句"这个中间单位**。

## 2. 人类语言产生的增量性（Levelt 模型）——他山之石，但只借机理不借实现

Levelt 的言语产生模型是**并行级联（cascade）**，不是流水线阻塞：

1. **概念化器（Conceptualizer）**：产出"前语言消息"（preverbal message）——
   宏观规划（说什么：目标／命题）+ 微观规划（怎么说：言语行为、信息结构、已知/新信息）。
   **它不停**：当前句还在被发音时，它已经在规划下一句。
2. **构形器（Formulator）**：语法编码（取词元 lemma、建句法）→ 音韵编码（音韵词、韵律结构）。
   它消费概念化器吐出的**片段**，而不是等整条消息。
3. **发音器（Articulator）**：把"语音计划"执行成连续发音动作流。
4. **自我监听（Self-monitor）**：监听自己说出的内容，触发**自我修正（self-repair／改口）**——
   "说到一半改口"在人类是常态，不是异常。

三条关键机理，本方案只借这三条（不借任何实现、不引任何神经模型）：
- **级联而非阻塞**：上游产出一片，下游立刻加工一片，各级时间上错位；
- **前瞻窗口（look-ahead）**：下一句在上一句未说完时已经开规划；
- **增量可修订（incremental revision）**：**已发声的不可撤回，未发声的可改**——改口发生在尾部。

**对应结构在 AHI**：把"脑→嘴"这条一跳，拆成 `概念化 → 消息 → 短语 → 韵律 → 发音` 五级，
外加一条**监控旁路**（自我监听）。见 §3。

## 3. 方案：五级流水线 + 监控旁路（含各级数据结构）

### 3.1 总结构

```
        ┌──────────── 修正事件（改口/停顿/抢话/撤回）────────────┐
        │                                                        │
  ①概念化G ──▶ ②消息M ──▶ ③短语P ──▶ ④韵律Y ──▶ ⑤发音A ──▶ 声音
  (意图/命题)  (小句语义)  (词序计划)  (音节帧)   (10ms波形)
      ▲                                                       │
      └────────────── ⑥监控S：比对"说的" vs "想的" ◀──────────┘
```

六级各占一条独立线程/循环，**只经共享工作区读写耦合，互不调用、互不等待**
（与 `共存态.py:4-24` 的红线一一致）。级间传递的不是"整句"，是**"已提交前缀 + 可改尾部"**。

### 3.2 每一级的数据结构（具体字段）

统一约定：每一级的状态都是一个**小小的局部寄存器**，含三段——`已提交 / 在途 / 待规划`，
并带一个 `版本` 令牌。以下为设计用伪结构（**设计，不是对既有文件的改动**）。

**① 概念化级 G（对应脑的意图层，扩展现有意图槽）**
```python
G = {
  "当前句": {            # 一个命题/一次"要传达的东西"，不是字符串
      "句柄": "U17",      # 本轮话语号
      "命题": ["动作:点", "对象:句柄E3", "评注:全新"],
      "指代": {"它": "E3"},          # 指代锚定到活句柄（跨模态指代）
      "情感": ...,        # 引用共享核心/社会情感（05 提供）
      "版本": 41,
  },
  "目标栈": [...],        # ≤4，扩展现有 目标栈
  "在途意图": [...],      # ★新增：尚未提交到话语/动作的意图，可撤回
  "信号": None,           # ★新增："改口"|"停顿"|"抢话"|None（监控写入）
}
```
码位：当前句论元 3~6 + 栈 4×3 ≈ **8~15**，装成 **1~2 个小束向量**。

**② 消息级 M（微规划：小句语义单元）**
```python
M = {
  "块": [               # 当前小句（一个 clause）的语义槽，有序
      ("主",  码(当前焦点)),
      ("谓",  码(动作词)),
      ("宾",  码(对象)),
  ],
  "已知/新": 位掩码,     # 信息结构（哪个是已知信息、哪个是焦点）
  "前瞻": <下一个块，草稿>,   # ★前瞻窗口：下一小句在上一小句未定稿时已开草稿
  "版本": ...,
}
```
码位：当前块 4~8 + 前瞻 4~8 ≈ **8~16**，**2 个小束**。

**③ 短语级 P（语法/词序：把语义槽排成有序词表）**
```python
P = {
  "短语": ["我想", "点一下", "这个"],   # 有序词/词元序列，≤7
  "可改尾": ["这个"],                    # ★尾部指针：只有尾段允许被替换
  "指代锁定": {"这个": ("E3", 版本)},    # 指代在哪一句柄上锁定
  "版本": ...,
}
```
码位：≤7 词 + 前瞻短语 ≈ **8~14**，**1~2 小束 + 序码（用 `绑` 的循环移位做位置绑定，见 `共存态.py:121-129`）**。

**④ 韵律级 Y（音节帧 + 前瞻窗口）**
```python
Y = {
  "音节队列": [                       # 前瞻窗口 = 3 音节（不是整句！）
      {"音": "dian", "调": 3, "参数": {8 参数档位}, "版本": ...},
      {"音": "yi",   "调": 1, ...},   # 在途
      {"音": "xia",  "调": 4, ...},   # 待规划
  ],
  "基线F0": ...,            # 由 05 提供，单一来源
  "韵律源": 句柄U17@版本41,  # ★与内容同源：韵律必须引用同一冲突版本
}
```
码位：8 参数 × 3 音节 = **24 档位**，但用 `meeting32/声带.py::数轴` 的"少维装多档"
（每轴 16×16=256 档，8 轴正交零串扰）→ **8 个数轴向量**，每轴可独立检索。

**⑤ 发音级 A（10ms 帧 + 谐振器连续状态）**
```python
A = {
  "当前帧参数": {f0,f1,f2,f3,幅,气声,声源,噪带,送气},   # 仅当前 1 帧
  "连续状态": {φ, 谐振器y[3], yn},                        # 连续量，非码位
  "已提交样本号": n,           # ★提交栅栏的位置（不可撤回点）
}
```
码位：**≈0**（连续状态，不是可检索概念）。

**⑥ 监控级 S（自我监听）**
```python
S = {
  "最近一致性": [{"句柄":"U17","内容码":…,"韵律源码":…,"相似":0.94}],
  "修正事件": ["改口:U17@词2", "撤回:U18"],
}
```
码位：2~4（事件/计数）。

## 4. 时序图（文字描述）——各级错位滑移，不是"想完才说"

设一拍 = 50ms（脑思维拍，`器官_脑.py:219`）。用户问一句，或脑自生意图后：

```
时刻(ms)   0     50    100   150   200   250   300   350   400
G概念化   [规划句N+1 ..................................][规划句N+2]
M消息              [块N定稿......][块N+1草稿→定稿...]
P短语                     [短语N词序][短语N+1词序]
Y韵律                            [音节窗N-1..N+1]
A发音                                   [音N-1 发声...............]
S监控                                   [监听........................]
```

要点：
- **各级在时间上错位**：G 在 0ms 就开下一句，而 A 在 ~250ms 才发第一个音；
- **同一刻多级同时活跃**：在 300ms 时，G 在规划 N+2、A 在发 N-1、Y 在排 N 的韵律——
  **同一时刻"脑子在想、嘴巴在说"**（所有者原话）；
- **首字延迟** = 从意图提交到 A 吐第一帧 ≈ 一~两级延迟 ≈ **150~300ms**，
  而**不是**等整句合成完（现方案 3s 句要 ~48000 次逐样本迭代，首字被拖到整句末尾）。

## 5. 与 `共存态` 的接口：新槽 / 新语义（关键交付）

现有六槽（`共存态.py:176-200`）是"只读最新值"的**弱耦合**，粒度太粗。全双工需要
**"句内中间态"**与**"可撤销意图"**。设计如下（**加两槽、扩两槽**）：

### 5.1 新增「话语槽」（说-侧流水线的全局快照）
```python
话语槽 = {
  "话语号": "U17",
  "阶段": "发声",              # 规划 | 发声 | 收尾
  "已说前缀": "我想点一下",     # ★不可撤回，只增不改（append-only）
  "在途": {"词": "这个", "撤销令": {"U17": 41}},  # ★说出来但还没出口的中间态
  "指代": {"这个": ("E3", 7)},   # 指代→活句柄+元素版本
  "版本": 41,
}
写者：短语级 P（单写者）。读者：发音级 A / 监控 S。
```
语义要点：**"已说前缀"与"在途"分离**——这是"说到一半"能成立的前提。

### 5.2 新增「韵律槽」（音节计划 + 前瞻窗）
```python
韵律槽 = {
  "音节队列": deque(maxlen=6),    # 前瞻窗 ≤3，滑动
  "基线F0": 165.0,
  "韵律源": ("U17", 41),          # ★同源令牌
}
写者：韵律级 Y。读者：发音级 A。
```
语义要点：队列**有界**（背压靠"窗满即停"，不靠阻塞）。

### 5.3 扩展「意图槽」：加"在途意图（可撤）"与"信号"
在现有 `写意图/取意图`（`共存态.py:285-305`）基础上，增加：
- `在途意图`：list，每项带 `状态 ∈ {草拟,已提交,已撤}` 与 `版本`；
- `信号`：`"改口"|"停顿"|"抢话"`，由监控写、各级读。
**可撤销意图**：动作侧由手在"剩余段"里改落点（已有先例），话语侧由 P 在"可改尾"里改词。

### 5.4 「表达槽」降格：从"整句队列"改为"消息块队列"
`排队说(整句)` → `排队消息(块)`：入队的是**语义块**（②的输出），不是成品字符串。
嘴不再"念整句"，而是与发音级协作**流式说出**。

### 5.5 新增「修正事件槽」（监控旁路的出口）
```python
修正事件槽 = deque(maxlen=16)   # 每项：{句柄, 类型:改口/撤回, 从第几词起, t}
写者：监控 S。读者：P（重排尾部）/ Y（重排韵律尾）/ A（若在提交栅栏后则忽略）。
```

**接口总原则**（与既有架构红线一致）：每个寄存器**单写者**、各持独立锁、
**锁内不做计算**、读者只取快照或"最新值"，**没有任何一级 join／call 另一级**。

## 6. 不打架的机制：门控 / 仲裁六规则

意图（G）／内容（M·P）／韵律（Y）三级并行，最大风险是**"说的和想的不一致"**。规则：

1. **单写者原则**：每个寄存器只有一个写者器官（G→概念化、M/P→构形、Y→韵律、A→发音、S→监控）。
   消除写-写竞争；跨级只能改"在途"，不能改"已提交"。
2. **版本令牌 + 单调提交**：意图带 `版本`；下游记录自己物化的是哪个版本。
   上游 bump 版本后，下游**只能改"在途/待规划"，绝不回改"已提交前缀"**。
3. **提交栅栏（commit fence）**：一个词一旦进入 A 且已产出样本，即**冻结**。
   与手完全同构：手用**当前实际光标**为新起点重算剩余段（`器官_手.py:133-151`），
   说用**当前已发声位置**为新起点重算剩余韵律——**已走过的不可改，剩余的可改**。
4. **同源约束**：Y 的 ΔF0／重音必须引自**G 的同一意图向量与同一版本**（`韵律槽.韵律源`）。
   监控 S 校验 `相似(内容码, 韵律源码) ≥ 阈值`，否则判为"说想不一致"，触发修正。
5. **仲裁优先级**：`修正事件 > 意图更新 > 常规流`。收到"改口"→ 各级**冲刷在途尾部**、
   以提交栅栏为界保留前缀、按新版本重排尾段。
6. **背压靠队列深度，不靠阻塞**：A 落后→Y 的窗满即停推→M 降速——但每一级都**只轮询槽、永不等待他级**
   （沿用 `共存态.py` 的弱耦合纪律），因此"不打架"的同时**不引入新的串行点**。

## 7. 与手的耦合：嘴能不能像手"移动途中改落点"那样"说到一半改词"？

**手已经证明可行**：`器官_手.py::_纠偏`（131-187）每拍读元素最新位置，
`_重定终点`（133-151）以当前实际光标为新起点重算最小急动度剩余段——**位置连续、无瞬移**，
纠偏计数写回动作槽（`自检.py::A3` 已验）。

**嘴的同构机制（设计）**：发音级每 10ms 帧读韵律槽最新目标；
若目标音素/词改了，且改动落在**尚未发声的尾部窗口**，则以**当前已发声位置 + 谐振器连续状态**为新起点，
重算剩余韵律帧并继续——不跳、不断，只是平滑改向。**这就是"说到一半改词"。**

**但存在硬障碍，必须点名要求解决**：`meeting32/声带.py` 目前是**整句批量合成**——
- `音节帧()` 对**整文本**一次性 `lazy_pinyin`（`:249`）；
- `合成波形()` 对**整句**逐样本 Python 循环（`:365, 406-468`），且**不保留跨调用状态**；
- `器官_嘴.py` 走 SAPI 同步 `Speak`（`:148-153`），**整句不可分割**。

**要求（对 05 发声专家）**：声带必须提供**流式发音 API**——
`开流()` → `推帧(帧参数)` → `改帧(新帧参数)` → `收流()`，
内部用**持久化的对称/谐振器状态**（把 `合成波形` 改成跨调用保持 `φ, y, yn` 的"步进"），
并暴露**帧级提交栅栏**。**在整句合成被改造为流式之前，"说到一半改词"无法真正落地**（见 §10 诚实边界）。

## 8. 容量账（核心论点）：全双工是加剧容量压力，还是缓解？

### 8.1 先厘清 HDC 容量律的适用范围
`D=1024` 的容量参考是**"单次捆绑检索"**的容量：干净 N ≲ 0.1·D=100，勉强 N ~ 1000。
**它约束的是"一次 bundle 里塞多少还能被干净检索"，不是"整机能存多少概念"。**
把 10³~10⁴ 个东西**捆进同一个向量**去查——才会撞墙。这正是朴素求和会"炸容量"的机理。

### 8.2 我的方案：每一级只持有一小窗（逐级码位表）

| 级 | 时间粒度 | 同时持有的局部状态 | 可检索码位 | 载体（寄存器） |
|---|---|---|---|---|
| ① 概念化 G | 句/命题 | 当前句 + 栈≤4 + 在途意图 | **8~15** | 1~2 小束 |
| ② 消息 M | 小句 | 当前块 + 前瞻 1 块 | **8~16** | 2 小束 |
| ③ 短语 P | 短语 | 当前短语≤7 词 + 前瞻 1 | **8~14** | 1~2 小束 + 序码 |
| ④ 韵律 Y | 音节 | 前瞻窗 3 音节 × 8 参数 | **24 档位**（=8 数轴，每轴 256 档） | 8 数轴向量 |
| ⑤ 发音 A | 10ms 帧 | 当前帧 + 谐振器连续态 | **≈0**（连续量，非概念） | 6 个 float |
| ⑥ 监控 S | 事件 | 最近一致性/修正事件 | **2~4** | 计数/事件 |
| **合计** | — | — | **≈50~70 码位 / 15~25 个寄存器** | — |

### 8.3 结论：**不加剧，反而缓解**——靠语气"流水线局部化"

**（a）每次检索的负载被压回干净区**：
任一级任一时刻只对**自己那一小窗（≤16 项）**做检索，远在 0.1·D=100 的干净区内。
反观"全局大向量"方案：若把"当前整句+整句韵律+整句计划"捆成一个束，就是 **100~200 项**，
直接落进降质区。**局部化把每个束的量从 10¹~10² 降到 10¹ 以内。**

**（b）容量 ≠ 单束容量，而是"寄存器数 × 寄存器容量"**：
把状态**分寄存器**存放，各用**独立码本**，则单个寄存器内的检索互不干扰；
整机容量随寄存器数**可加**，而**任何一次 lookup 的束大小不涨**。
这正是 C4 要的**"非线性容量增益"**（增益来自结构，不来自扩维）：
不扩 D，只加"小抽屉"的个数；每个抽屉的查询质量不变。

**（c）代价明确、可被 03 量化**：
- 内存：~25 寄存器 × 1024 维 × 4B ≈ **100KB**（可忽略）；
- 延迟：每级局部检索 <1ms（与 `meeting32/数轴.解码档位` O(S·D)≈26 万次乘加 <2ms 同量级）；
- 复杂度：寄存器数↑、需要版本/一致性协调（这是全双工真正的"成本"，不是显存）。

**（d）比 1024 基线的倍数**：我的方案**不扩 D**（N=1）；
它把"同时进一个束的量"从 10³→10¹（约 **100 倍**缓解），
把"首字延迟"从"整句合成时长"降到一级延迟（约 **10 倍**改善）。

### 8.4 诚实界定：我只解决"生成侧并发容量"
本方案**不**解决"知识本体（数百~数千概念）"与"感知（~150 元素/帧）"的容量——
那是 01／02 专家的阵地。我只证明：**生成侧（意图→话语→韵律→发声）的并发，
用局部小状态即可承载，不会给全局容量添乱。** 这是本角的边界，不许含糊。

## 9. 可失败判据（≥3，均可真失败、含量化门槛）

> 全部可在 `自检.py` 的同款设施上运行（合成屏 + 演练手 + 假时钟），不需要真屏真麦。

### 判据 F1 · 首字延迟（证明不是"先想后说"）
**定义**：从"意图提交"（G 版本 bump 且 `发声=真`）到 A 吐出**第一帧发音参数**的时间差。
**门槛**：中位数 **≤ 300ms**，且 **P95 ≤ 500ms**（对齐简报 §3 的发声首字预算）。
**失败模式**：只要任一级（尤其声带）退化为"等整句"——首字延迟会骤增到整句合成时长（秒级），
**直接判失败**。这条是 C5 的**直接证伪器**。
**量化采集**：每句记 `(意图t, 首帧t)`，跨 ≥20 句统计分布。

### 判据 F2 · 说做一致率（证明"说的"与"做的"不打架）
**定义**：凡话语中陈述了下一步动作（含 `指代`→句柄）的，比对**随后提交并执行的动作意图**
是否指向同句柄/同目标。`一致率 = 命中配对 / 总配对`。
**门槛**：**≥ 0.90**（≥20 次配对）。
**失败模式**：G 与 M/P 版本漂移（说 A 却做 B）→ 一致率跌破阈值即失败。
**量化采集**：`话语槽.指代` 与 `动作槽.句柄/目标` 按时间窗配对。

### 判据 F3 · 中途改词可行性（证明"可改口"，且不retro-edit）
**定义**：脚本注入一次"尾部改口"（在词 2 处翻转内容）。
要求 A 的发音流出现**修正边界**，且边界**之前**的样本与旧版本**逐位一致**，边界**之后**匹配新内容。
**门槛**：脚本化测试中 **≥1 次改口成功**，且"已提交前缀"**逐位未变**（证明没回改历史）。
**失败模式**：若声带仍是整句批处理（不能流式）→ 无法产生修正边界，**判失败**。
这条会**如实暴露 §10 的障碍**，不遮掩。

### 判据 F4 · 并发不退化（不破坏既有 A1–A7 / W1–W6）
**定义**：在流水线全开下重跑既有判据。
**门槛**：`A1` 最长写 ms **< 50**；`A4` 手忙脑不停**过**；`W1` 脑不阻塞率 **≥ 0.8**；
新增槽的读写**不使任何既有"过"项翻成"未过"**。
**失败模式**：新槽引入跨级锁竞争或长写 → A1/A4/W1 退化即失败。

### 判据 F5 · 韵律-内容同源一致性
**定义**：逐音节校验 `相似(内容码, 韵律源码版本)`。
**门槛**：**≥ 95%** 音节同源（相似 ≥ 0.8）。
**失败模式**：Y 用了过期版本的意图（"语调还停在上一句的情绪"）→ 比率跌破即失败。

## 10. 诚实边界（哪部分我做不到 / 天花板在哪）

1. **声带整句批处理 vs 流式的冲突——可能无法 100% 解决**。
   `合成波形()` 无跨调用状态、逐样本整句循环（`meeting32/声带.py:365-468`）；
   改成流式需把谐振器/相位状态外提并保持**确定性**（C7），
   而"改帧"落在**元音中段**时，接缝很可能产生**可闻毛刺**。
   诚实预判：**词/短语边界改口可行；音节内部改口可能毛刺；音素中途改口很可能失败。**
2. **SAPI/`pyttsx3` 路径根本无法中途改词**（整句同步 `Speak`，`器官_嘴.py:148-157`）。
   该路径只能"取消尚未开始说的整句"（队列级撤回），**做不到句内改口**。
   → 真正的"改口"**必须走原生声带**，SAPI 只能作降级备份。
3. **已发声的不可撤回**。全双工不能"收回已出口的话"——指代若在说出口后世界变了，
   只能改后续、不能改已说。这与手的"已走过轨迹不可改"同理，是**物理下界**，非实现缺陷。
4. **容量账只覆盖生成侧**。知识/感知的容量不归我，§8.4 已划界；若有人拿"生成侧局部化"
   去声称"整机容量已解决"，那是**越界**，请主持作废。
5. **实时性受 GIL 约束**。`A` 的 100Hz 循环 + Python 逐样本内核，与眼（GPU 18Hz）、
   手（60Hz）同处 Python 层，**真实时序抖动未测**——需要 03 的证据（见 §11），我**不打包票**。
6. **前置依赖未就绪**：流式声带 API、韵律槽、监控级当前都**不存在**；
   本方案是"待建"，不是"已验"。**任何"已实现"的话都不许说。**

## 13. 结论

1. **全双工的结构** = **五级局部小状态流水线（概念化→消息→短语→韵律→发音）+ 监控旁路**，
   级间传"**已提交前缀 + 可改尾部**"，以**提交栅栏**划出"不可撤回／可修订"的边界。
2. **容量账结论**：**不加剧，反而缓解**。全双工迫使状态**分寄存器局部化**，
   每次检索的束 ≤16 项（干净区内），而不是把 10³ 塞进一个 1024 向量（降质区）；
   容量增益来自**结构（寄存器数）而非扩维**（C4）。代价是寄存器数与协调复杂度，不是显存。
3. **可失败判据**：F1 首字延迟、F2 说做一致率、F3 中途改词、F4 并发不退化、F5 韵律同源（共 **5 条**）。
4. **诚实边界**：声带整句批处理与流式的冲突是本方案最大未决项，**可能只能做到"词/短语边界改口"**；
   SAPI 路径不可改口；已发声不可撤回；容量账只覆盖生成侧；实时性受 GIL 约束、待 03 验证。
5. **与所有者原话的对齐**：他说"**先想，再说出口**"不对——本方案取消"整句"这个中间单位，
   让**想、说、做在同一时刻错位并行**；他说"**脑子在想、嘴巴在说、手在动、眼睛在盯屏，同一时刻发生**"——
   本方案正是为这"同一时刻"给出可实现的寄存器与栅栏。
