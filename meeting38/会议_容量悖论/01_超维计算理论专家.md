## 0. 一句话结论（TL;DR）

```
① 容量上限的数学 = 叠加（bundle）干扰律：
     一个 D 维双极向量里，能被同时可检索的项数 N 满足   N · ln N  ≲  D / π
     D=1024 → N_clean ≈ 70~80；降质可辨 N ≲ 0.6·D ≈ 600；N ≳ 0.8·D 崩。
     这道墙是信息论的，任何编码都拆不掉——它是「一个向量」的墙，不是「系统」的墙。

② 破局不是「把更多东西塞进一个向量」，而是「容量搬家」：
     把容量从【单向量叠加】搬到【结构化可寻址存储 + 稀疏的注意力工作区】。
     向量的角色从「仓库」变成「地址 + 句柄」。

③ 三个非线性增益（都不违反 C4）：
     · 层次寻址（多级编码）：总容量 ∝ B^ℓ，单拍代价 ∝ ℓ·B·D（对数/线性），容量指数增长。
     · 因子化绑定（role⊗filler）：O(R·F) 组合 → O(R+F) 原子。
     · 多轴组合（数轴 f⊙c）：一根 D 向量装 ~√D 档/轴，S1·S2 组合档数、代价 O(S·D)。
     外加：稀疏码只涨【码本大小/速度】，不涨【叠加容量】——务必别用错地方。

④ 我的方案 FSW（分层因子化稀疏工作区）：固定 D=1024 不变，靠 L0 原子码本 + L1 因子化记录
     + L2 有界工作区（K 槽，补上项目缺失的「竞争/瓶颈」）+ L3 深度 ℓ 目录树。
     有效可检索码位 ≈ 10^4 ~ 2×10^5，较 1024 基线（干净 75 / 勉强 10^3）提升约 20×~200×（≈1.3~2.3 个数量级）。
     代价：单拍 += 0.05~1ms（GPU），显存 += 0.1~1.2GB。全在 C6 预算内。
```

## 1. 容量上限的数学（唯一问题的一半）

### 1.1 精确推导：双极叠加的检索保真度

设码原子 `x_i ∈ {±1}^D`，i.i.d. 均匀（Rademacher）。把 N 项叠加（bundle，多数表决）成
一个向量：

```
s = sign( Σ_{i=1..N} x_i )          # 项目现有 编码器.束 就是这条，np.sign(sum)
```

问：从 s 里能不能把第 j 项认出来？度量用余弦 `cos(s, x_j)`。

逐坐标分析。因为 s 与 x 都是单位范数（除以 √D），

```
cos(s, x_j) = (1/D) · Σ_c  s_c · x_{j,c}
```

固定某坐标 c，令 `v = Σ_{i≠j} x_{i,c}`（N-1 个 ±1 之和，近似 N(0, N-1)）。则

```
E[ s_c · x_{j,c} | x_{j,c}=+1 ] = P(v > -1) - P(v < -1) = 2·Φ(1/σ) - 1     , σ²=N-1
E[ s_c · x_{j,c} | x_{j,c}=-1 ] = 同值（对称）
∴ E[ cos(s, x_j) ] = 2·Φ(1/σ) - 1   ≈  (1/σ)·√(2/π)
```

于是（大 N）：

```
  μ_N  ≜  E[cos(s, x_j)]  ≈  √( 2 / (π·N) )            …… 信号（成员相似度）
```

**信号随 N 衰减为 1/√N。** 这不是线性掉，是**平方根掉**——这就是"N 稍大就变糊"的数学来源。

再看干扰：对非成员 k≠j，

```
  cos(s, x_k)  ≈  0  （均值），标准差  σ_0 = 1/√D       …… 串扰（非成员相似度）
```

判"第 j 项是成员"的正确条件是：**成员相似度要压过 N-1 个干扰项里的最大值**。
N 个 N(0, σ_0²) 变量的最大值 ≈ `√(2 ln N)·σ_0`。写成判决余量（SNR）：

```
  SNR(N) = μ_N / σ_0 = √( 2/(πN) ) · √D = √( 2D / (πN) )
```

要求 `SNR > √(2 ln N)`，即：

```
  ┌──────────────────────────────────────────────────────┐
  │   2D/(πN)  >  2 ln N     ⟺     N · ln N  ≲  D / π     │   ← 干净容量定律
  └──────────────────────────────────────────────────────┘
```

**这就是"为什么 N~0.1D 恭敬衰退、N~D 崩"的精确形式。** 它比"信噪比 ~√(D/N)"更精确之处在于
多出的 `ln N` 因子——它来自"要在 N 个候选里取最大"这个**选择动作**。所以真正的 SK 律不是 √(D/N)，
而是 `√(D/(N ln N))`。

### 1.2 数值曲线（D=1024，纸面推演）

```
D=1024:  D/π ≈ 325.9     解 N·lnN = 325.9  →  N_clean ≈ 75

  N     μ_N=√(2/πN)   SNR=√(2D/πN)   门槛√(2lnN)    判决区
 ───────────────────────────────────────────────────────────
  10      0.252           8.07          2.15        干净（err≪1e-3）
  30      0.146           4.66          2.61        干净（err~1e-3）
  50      0.113           3.61          2.80        干净
  75      0.092           2.95          2.94        ★临界（err~1%）
 100      0.080           2.55          3.03        降质（err~5–10%）
 150      0.065           2.08          3.17        降质（err~20–40%）
 300      0.046           1.47          3.38        勉强（err>50%）
 600      0.033           1.04          3.58        近崩
 1000     0.025           0.81          3.72        崩（信号<噪声）
```

预测总结：**干净区 N≲75；可辨区 75≲N≲600；崩塌区 N≳600。**
与所有者口述"几百到 1000"一致，但更严：**"干净"只有 ~75，不是几百**——I 号专家要把这个偏差点明。

### 1.3 三条"不可翻越"的铁律（先立墙，再谈翻墙）

```
{R1} 单个 D 维向量的同时可检索项数 ≤ ~0.1D（干净）。任何绑定/稀疏/多级都改不了这条——
     因为它由「D 个坐标的自由度 + 多数表决的损失」共同决定，是信息论量级，不是编码技巧。
{R2} 想要 M 个「可命名」的概念，不需要把它们塞进一个向量——M 由【码本大小】与【读取代价】约束，
     而码本的成对正交容量可到 ~exp(D·θ²/4)（θ=可容忍最大串扰）——对 D=1024 是天文数字。
     ★ 悖论的根因：把【码本问题】当成了【叠加问题】。二者是两回事。
{R3} 扩容 1~2 个数量级只能来自「结构」：层次深度、因子化、多轴组合。
     线性扩维（C4）之所以被否，是因为它把 Δ容量 与 Δ算力 锁成 1:1；结构化的 Δ算力 是次线性的。
```

## 2. 工具箱评述与我的裁决（逐项）

### 2.1 稀疏码 SDR —— 结论：**不要用它做叠加层，用它做码本层**

设 k-sparse 码：每码仅 k 位非零（k≪D）。直觉上"稀疏占用少 → 更省"，但这是误区。看叠加：
把 N 个 k-sparse 码相加（非阈值化，保留幅值），某个成员与 bundle 的内积

```
  <bundle, x_j> = |x_j|² + Σ_{i≠j} <x_i, x_j>      # 信号 = k，串扰均值 ≈ N·k²/D
  SNR_SDR ≈  k / √( N · k²/D ) = √( D·k / N )·(1/√k) ... 归一到每比特信息密度后
```

把"每维承载的信息"归一化后可得：**在 k=D/2（即稠密双极）附近，叠加容量/比特取最大。**
稀疏（k≪D）会**降低**单向量叠加容量。数学直觉：稀疏码的"活跃位"重合概率是 k²/D，
串扰压不下来而信号只有 k，得不偿失。

**裁决**：SDR 的正确用武之地是 **L0 原子码本层**，因为：
- 码本可区分码数 ~ C(D,k)（组合数），k=D/20 时 C(1024,51) 已是 ~10^70 量级 → "可命名概念"几乎无上限；
- 稀疏位运算（AND/OR/交集）廉价，适合超大数据词典的**集合成员判定**；
- 但它**不提升**工作区叠加容量。
> 一句话：**稀疏买的是"码本规模与速度"，不是"一次能想几件事"。别用错楼层。**

### 2.2 因子化/绑定（role ⊗ filler）—— 结论：**必用，这是 O(N²)→O(N) 的钥匙**

现成算子：`共存态.py::编码器.绑(a,b,移位)` = 按位乘 + 循环移位，双极闭环。关键性质：

```
自逆性：  R ⊙ R = (+1,+1,...,+1) ≡ 1⃗       （全 1 向量）
解绑：    R ⊙ (R ⊙ F) = F   精确复原（无训练、无误差传播）
```

**容量数学**：一个"记录"= P 个角色-填充绑定的束：

```
  record = Σ_{p=1..P} ( R_p ⊙ F_p )
  解绑：R_p ⊙ record = F_p  +  Σ_{q≠p} (R_p⊙R_q)⊙F_q
                            └─ 串扰项，R_p⊙R_q 是新的近正交随机向量 ─┘
```

于是**一条记录内部等价于一个 P 项叠加**，受 §1 的 N·lnN 律约束（P≲75 干净）。
但它带来的收益是**爆炸性**的：

```
无绑定：要为 (角色×填充) 的每个组合分配独立码位 → 需要 R·F 个码位（组合爆炸 O(N²)）
有绑定：只需 R 个角色原子 + F 个填充原子 → 需要 R+F 个码位（线性 O(N)）
例：视觉 150 元素 × 4 属性 = 600 组合
    无绑定 600 码位；有绑定 150+4 = 154 码位。压缩比 ≈ 3.9×（元素越多越大）
```

**裁决**：所有"关系型/属性型"信息一律走 `绑`；只有"离散基元"才占独立原子。
这条直接消掉预算表里"元素间关系 组合爆炸 150²量级"那一行的绝大部分。

### 2.3 子空间分区 vs 全量拼接 —— 结论：**分区不增容量，只做「分配+隔离」**

会不会"视觉占一段、听觉占一段"就省码位？**不会。** 设把 D 分成 L 段，各段容 N_l：

```
  N_l ≈ 0.1·D_l     →     Σ_l N_l ≈ 0.1·Σ_l D_l = 0.1·D    （总量守恒，分区不乘）
```

**分区精确地把问题搬到了段内，总和不变。** 但它买到两样真东西：

```
(a) 隔离：跨模态串扰 = 0 → 检索某模态时干扰集只剩本段，噪声底由「段内 N_l/D_l」决定，
         于是可以按真实需求做非对称分配（视觉需多就给 60%，语言 20%…），而非均分。
(b) 独立时钟：段之间时间解耦 → 听觉 20Hz、手 60Hz、眼 60Hz 各写各段，不互相等待（呼应 C5 全双工）。
```

**裁决**：分区是**分配器**，不是**放大器**。放大必须靠 §2.4/2.5/2.2 的结构。

### 2.4 层次/多级编码（L=4 先例）—— 结论：**这才是数量级的来源**

先例：`gpu_backend.py:162` `level=4 ⇒ 四分块多级编码`，`x̃ = sign(Φ_L @ u − c_vec·‖u‖)`，
"每 1 bit 扩为 4 分块"，K3 教训：**增益来自码丰富度，而非幅值阈值**。

**机制解释（我把 L=4 重新诠释为"深度 ℓ=1 的层次寻址 + 码丰富度"）**：

1. **码丰富度**：把 D 分成 L 个分块、每块独立编码 → 一个向量能承载的**符号组合数**从 2^D 涨到
   ~A^D（A 为每块字母表大小）。这一层只放大**码本**（可命名概念数），不直接放大叠加容量。
2. **层次寻址（关键）**：真正把容量做成数量级的是把"一个平铺束"改成"一棵树"：

```
   根束 → 选出桶地址（B 选 1）
     └ 桶束 → 选出子桶地址（B 选 1）
         └ …共 ℓ 层…
             └ 叶子束 → 装 N_b 条记录（N_b ≤ N_clean ≈ 75）

   总可寻址记录数  ≈  B^ℓ · N_b          （指数！）
   单次读取代价    ≈  ℓ · (B·D) + P·D     （对数/线性！）
```

   因为**每一拍的叠加只发生在一个桶内（≤N_b 项）**，永远不触碰 §1 的墙；而"总容量"由树的叶子数
   决定，随深度 ℓ **指数增长**。这就是 C4 要求的"非线性容量增益"——扩的是**结构深度**，不是向量维度。

3. **提升多少倍、代价多少**：

```
   相对平铺束：容量增益 ≈ B^ℓ · N_b / N_clean
              B=16, ℓ=3, N_b=50 :  4096 × 50 / 75  ≈  2730×
   代价：每拍多 ℓ 次 cleanup（每次 B·D 次乘加）= 3×16×1024 ≈ 4.9×10^4 次乘加 ≈ 0.05ms(GPU)
   ★ 于是 D 维不变，容量涨 3 个数量级，延迟只涨 0.05ms。这才是破 C4/C6 悖论的机制。
```

**裁决**：采纳。把 L=4 的"分块"**推广为树的 ℓ 层**；分块做**段隔离**，层级做**容量放大**，两者分工。

### 2.5 双轴/多轴组合（声带.py 数轴类）—— 结论：**连续量的专用放大器**

先例：`声带.py:46-98`，`f_{k1} ⊙ c_{k2}`，S1=S2=16 → **16×16=256 档**，只用 **2 个基向量对**
（`_f链`/`_c链` 各 17 个原型），解码 O(S·D)≈26 万次乘加 **<2ms**。这编码了**度量空间**（相邻档 cos 线性衰减）。

**容量规律**：

```
字母表放大：a 根轴、每轴 S 档 → S^a 档，用 a·S 个原型向量
  双轴 S1=S2=S:  S² 档 / 2S 原型  →  放大比 ≈ S/2
可分辨上限（关键约束）：相邻档 cos 间距 = 1 − 2·翻转/D，要压过噪声 1/√D：
   2·翻转/D > 1/√D  →  翻转 > √D/2  →  单轴可分辨档数 S < √D ≈ 32
   D=1024 → 单轴 S*≈32，双轴组合 S*²≈1024 档（但受格点打包，实用 256–512 档）
```

**裁决**：`数轴`用于**连续量**：韵律 8 参、位置 x/y、强度、时间戳、声区、送气量……每个连续量 = 一根
双轴数轴（2 对基向量 + 256 档）。8 个韵律参数 → 16 对基向量，装下 8×256 状态，**不占 8×N 码位**。

### 2.6 可变维度 —— 结论：**给"可变"一个可操作定义（不动 D）**

所有者直觉："应该是可变向量，而非定死"。物理 D 必须固定（否则触发 C4 的线性扩维）。可操作化 = 三旋钮：

```
  K(t) ∈ [1, K_max] : 当前工作区活跃槽数（注意力可及项数）
  ℓ(t) ∈ [1, ℓ_max] : 当前寻址深度（分辨率/祖先层级）
  L(t)              : 连续轴档位数（2.5 的 S）
  状态 = ( 路径 P(t) ：ℓ 个桶原子
         , 工作区 W(t)：K 个活跃记录句柄及其束
         , 载荷 A(t) ：各轴当前档位 )
  总可表示 ≈ B^ℓ(t) · N_b ;  单拍代价 ∝ ℓ(t)·B·D + K(t)·P·N_bucket·D
```

**"可变"= 活跃占用与分辨率深度可变，物理维度不变。** 控制器（显著度门）按 50ms/16ms 预算
逐拍选 (K, ℓ) —— 想得多就加 K、看更细就加 ℓ，付出的是增量算力，而**不是**把 D 改大。
→ 这同时满足 C4（无线性扩维）与 C6（代价可控），并把所有者"可变向量"落成工程参数。

## 3. 方案：FSW 分层因子化稀疏工作区（可照实现）

### 3.1 总原则

> **容量搬家**：向量的角色从"仓库"降级为"地址 + 句柄"。
> 需要**同时**读的极少（K≲40），放进工作区束；需要**长期**存的多（10^4~10^5），放进码本 + 树。
> 用 §1 的墙保护工作区，用 §2.4 的树放大总容量。

### 3.2 数据结构（全部基于既有 `编码器`，D=1024 不变）

```
L0 原子码本  atoms: { atom_id -> int8[D] }        # 复用 编码器.字码/_新码；或 SDR 变体(尾部)
             类型标签 {role, filler, bucket, handle, emotion, intent...}
             索引：role → 该 role 下的 filler 候选桶（哈希分桶，见 3.3）
L1 记录层    records: { rec_id -> Record }
             Record = {
               句柄   : int64  (稳定ID，跨帧复用；视觉元素"跨帧稳定句柄"放这)
               束     : int8[D] = 束([ R_role ⊙ F_filler , ... ])   # role⊗filler 绑定后束
               指针   : bucket_id   # 落在 L3 树哪个叶子
             }
L2 工作区    W = 束([ K 个活跃记录的 束 ])  +  路径 P(ℓ 个桶原子)  +  载荷 A(各数轴档位)
             # 唯一每拍刷新、唯一受 §1 墙约束的向量。K_max ≈ 40（含竞争/瓶颈，见 3.3 门）
L3 目录树    depth ℓ, branching B:  每内部节点 = 束([B 个子桶原子])，叶子 = 束([≤N_b 条记录束])
             桶原子由 sha256("桶|路径") 确定性导出（复用 声带._基向量 同律）
数轴轴       复用 声带.数轴：{param -> 数轴(键,D,S1=16,S2=16,下界,上界)}，装连续量
```

### 3.3 关键算法（步骤 + 常数）

```
【A. 写一条记录 write(role_filler_pairs, 句柄)】
 1. 对每对 (R,F)：取 R=atoms[role]（无则新建），F=atoms[filler]；v_p = 绑(R,F)   # 复用 编码器.绑
 2. 束S = 束([v_1..v_P])                                                          # 复用 编码器.束
 3. 指针 = tree.insert(束S)                                                       # 见 B
 4. records[句柄] = {束:S, 指针:指针} ; atoms[句柄]=哈希(句柄)→原子  # 跨帧稳定句柄

【B. 目录树插入/查询 insert/query(向量 q)】
 1. cur = root ; path = []
 2. for level in 1..ℓ:                                                            # ℓ_max=3（默认）
      子 = cur.children (B=16 个桶原子)
      i* = argmax_j 余弦( q , 子_j )     # 复用 编码器.批相似；B·D=1.6e4 次乘加
      cur = 子[i*] ; path.append(i*)
 3. 叶子束 L = cur.bundle ; 在叶内 cleanup：i* = argmax_i 余弦( q , 记录束_i )   # ≤N_b=50 项
 4. return records[叶子束元数据[i*]]

   总代价 ≈ ℓ·(B·D) + N_b·D = 3·16·1024 + 50·1024 ≈ 1.0e5 次乘加 ≈ 0.05–0.1ms(GPU)

【C. 因子化解码 decode(记录束S, 角色R)】
 1. raw = 绑(R, S)                  # 自逆 → 得到 F + 串扰              # 复用 编码器.绑
 2. 候选集 = atoms_by_role[R] 的哈希桶（≤N_bucket=1000）
 3. F* = argmax_f 余弦(raw, f)      # 复用 编码器.批相似；代价 ≤1000·1024 ≈ 1e6 次乘加 <0.2ms
 4. return F*（要做连续量则转 第 5 步）
 5. 若 F 属于连续量：档位 = 数轴.解码档位(raw)   # 复用 声带.数轴，O(S·D)≈2.6e5 <2ms

【D. 每拍工作区刷新（20Hz 思维 / 60Hz 手）】
 1. 显著度门：对候选记录算 salience（新旧/强度/意图相关），winner-take-all 选 K≤K_max 条
 2. W = 束([ 选中记录的 束 ])   # 只叠加 K 项，保 §1 干净：K=40 → SNR≈4.0，干净
 3. 路径 P、载荷 A 各自由对应器官并发写（各段独立锁，复用 共存态 细粒度锁）
```

## 5. 可失败判据（≥3，均含量化门槛，可真实失败）

### 判据 F1 —— 容量压力测试（核心，必测曲线）
塞满 N 个概念进**单个叶束**，测 top-1 检索保真度与判决余量 SNR：

```
  N:      30      50      75      100     150     300     600     1000
明文门槛（理论预测）：
 top-1 ≥  0.99    0.99    0.97    0.90    0.70    0.30    0.10    ~0     ← 纸面推演
 SNR  ≥   4.66    3.61    2.95    2.55    2.08    1.47    1.04    0.81     ← §1.2
【通过条件】实测在 N=75 处 top-1 ≥ 0.95 且 SNR ≥ 2.8；且曲线在 N∈[300,1000] 单调跌至 <0.3。
【失败条件】（任一即理论被证伪）：
 (i)  N=75 时 top-1 < 0.90（说明 μ_N 定律偏乐观，N_clean 实际更低，方案须下调 N_b）；
 (ii) 曲线不在 N≈600±200 出现"拐点/崩溃"（说明我推导的 lnN 判决律不对，须重推）；
 (iii) 到 N=1000 仍 top-1>0.5（说明存在我未建模的增益 → 该线索须回收进理论）。
```

### 判据 F2 —— 层次寻址增益（证明"树真的解耦容量与延迟"）
在 M 条记录中随机检索，测 top-1 与 p95 延迟：

```
【通过】B=16, ℓ=2, M=1.3e4：top-1 ≥ 0.99，p95 ≤ 1ms(GPU)/≤5ms(CPU)；
        B=16, ℓ=3, M=2.0e5：top-1 ≥ 0.99，p95 ≤ 2ms(GPU)。
【失败】(i) 要达 0.99 所需 ℓ > 3（即每叶被迫塞 >N_b=50 → 树没解耦，退化为平铺）；
       (ii) 延迟随 M 线性增长（应随 M 仅对数增长：ℓ=log_B M）；
       (iii) 桶误分配导致检索到错叶（桶原子余弦分辨 < B 个候选的能力，即 B 逼近 0.1D）。
```

### 判据 F3 —— 因子化压缩与解绑保真
150 元素 × 4 属性：

```
【通过】用 ≤ 154+4 个原子装下；单记录 P=4 时解绑属性 top-1 ≥ 0.99；
        同一记录 P 涨到 24 字段仍 ≥0.95（P≪N_clean）。
【失败】(i) 字段 P>8 就掉到 <0.90（说明绑定串扰被低估，O(N) 压缩不成立）；
       (ii) 需为组合分配独立原子（退化为 O(N²)，因子化失败）。
```

### 判据 F4 —— 数轴分辨率
```
【通过】单 D=1024 双轴数轴：256 档可分辨（top-1 ≥ 0.99），相邻档 cos 间距 ≥ 1/√D ≈ 0.031。
【失败】可分辨档数 < 128，或 3 根轴以上叠加解耦失败（说明 §2.5 单轴 S*<√D 的界更紧）。
```

### 判据 F5 —— 延迟/全双工不回退（C5/C6）

```
【通过】K=40 且 ℓ=3 时：思维拍 ≤ 50ms、手 ≤ 16ms、发声首字 ≤ 300ms；
```

## 9. 一页纸速览

```
问题：容量缺口 1~2 数量级，线性扩维(C4)/串行(C5)/外挂(C1-3)三条路被封。
数学：单向量叠加墙  N·lnN ≲ D/π  →  D=1024 干净~75；绝不能指望"一个向量装 10^4"。
破局：容量搬家——向量当地址，不当仓库。
      ① 因子化 role⊗filler：O(N²)→O(N)（150元素×4属性：600→154 原子）
      ② 层次寻址 tree(B=16,ℓ=3)：总容量 ∝ B^ℓ（≈4096 叶 ×50），单拍只 +3 次 cleanup(~0.05ms)
      ③ 多轴组合 数轴：256 档/轴，8 韵律参只吃 16 对基向量
      ④ 有界工作区 K≤40 显著度门：补上项目缺失的 GWT-2「竞争/瓶颈」
      ⑤ 稀疏码：只用于码本尾（10^5~10^6 概念），不用于叠加层（那会降容量）
结果：有效可检索码位 ~1.3×10^4 ~ 2×10^5，较基线 1000 提升 ~13×~200×（1.1~2.3 数量级）；
      代价 单拍 +0.05~1ms / 显存 0.3~1.2GB。满足 C1–C8。
判据：F1 容量压力曲线(核心) / F2 树解耦 / F3 因子化解绑 / F4 数轴分辨率 / F5 延迟不回退 / F6 确定性。
边界：单向量墙不可翻（B1）；若需 10^3 项并发在聚光灯 → 失效；多处为纸面，交 F1–F4 证伪。
```
