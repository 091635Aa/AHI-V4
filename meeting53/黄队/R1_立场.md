## 0. 五条核心结论（先给结论，证据在后）

1. **「大余量」不存在：三线并行的第一约束是时间，且必须按 p90 立预算。** 全链 D=1024 一拍自身 **median 30.44 / p90 49.07ms**（p90/median = **1.61×**）[实测 R3]；G7 的 96.0ms 载体并发 200–384ms（**2.1–4.0×**）[实测]。**用 median 立预算 = 用自己的抖动骗自己** ⇒ 本队一律以 p90 立。
2. **96.0ms 判据载体在 100ms 时基下三线并行必然不可能**：缺口 **35ms**（100−96−正文12−调度6），**与未测的旁路由开销无关** ⇒ 这条结论不依赖任何未测假设。要它，只能把时基放到 **≥200ms** 且独占。
3. **N 脑账必须按「每脑真实增量」分列，不能按「引擎 180MB」外推**：全链 D=1024 的**每脑增量 = WS 227MB / commit 273MB**（不是引擎 23.98 + scratch 35.22 = 59MB）[实测 R3 差分] ⇒ **N=3 即 WS 709MB（破 320 线 2.2×）/ commit 836MB**。算得起的只有：**千层 D=256 的 N≤3**（WS 204 / commit 286 [推算]）、**D=64 的 N=5**（多进程 RSS 162.5 / commit 94.5 [实测 per-进程 × 推算]）。
4. **commit 口径不是矛盾，是线程池**：G5 的 **1252.2MB = 默认 16 线程**（numpy 线程池 **+490MB**）；锁 **OPENBLAS_NUM_THREADS=1** 后同一全链 2000 拍 = **306.11MB = 320 线的 95.7%**（"刚好踩线"）。⇒ **报告不锁线程数即 VOID**。「76% 未归因」也已实测：**81.8% 是 torch 常驻**（881.83/1077.88），不是全链内部。
5. **T1–T4 都判得起，T5 窄幅可行，一条最小子集 ≈135.4s（两趟已含）**：10 臂、单趟 65s、两趟 **135.4s**，余 164.6s（54.9%）[推算，载体取 千层 D=64 16.3ms/拍 上限口径]。**「算不起」共 9 条**（§5.3），其中两条是宪法级不可判而非算力（人脑复刻、跨硬件确定性）。

## 1. T1 · 主正文通道：实测代价

### 四件套 T1-A｜正文底座极便宜，瓶颈不在读出，在「词表规模」与「是否真是它自己的」
- **主张**：正文通道的**引擎侧**代价可忽略——`两区室核(D=256)` 单拍前向（3 令牌、迭代 1 步）**1.553ms/拍** [实测·本轮探针]；4 步 1.893ms、8 步 1.891ms（**4→8 步不再加价**）。⇒ 「每拍 1 个文本单位」在 100ms 帧里只占 **1.55%**。
- **证据**：`子代理/工程路径员.md` §0（[实测] 探针：import 33.3ms、构造 27.4ms、1.553/1.893/1.891ms）；码本读出 O(V·D)：V=512,D=256 ⇒ 131,072 乘加/拍 [推算]；V=4096 ⇒ 1,048,576 乘加 = 千层 D=256 主前向（6,303,744 [实测/解析]，`证据_千层.md:105`）的 **16.6%**。
- **反证**：①实测正文通道 >10ms/拍（帧的 10%）⇒ 本结论推翻；②词表被迫 ≥8192×512 → 码本 **16.8MB**，吃掉 120 拍残差（320−167.90−35.22 ≈ 117MB）的 14%，仍可行但须单列；③**最关键的反证不是资源而是内生性**：把正文换回 `AHI3/meeting41/实施/输出流.py:105-128` 六个手写池 + `_生成正文()`（:472-491，按 `拍%3` 取句）必须判 **内生度 FAIL**——该臂**便宜到 0 乘加**，所以「便宜」永远不能当通过证据。
- **算力代价**：+131,072～1,048,576 乘加/拍；码本 +0.5～4.19MB（V=512～4096 @D=1024 int32）[推算]；墙钟 **未测**（方案：CProfile 单函数 ×120 拍 ×3 次，独占 ≤30s）。**必须失败对照臂**：句池臂（`输出流.py`）预期 `MI(文本;状态) ≤0.05 bit/拍`、置换状态后文本变化率 ≤0.05。

### 四件套 T1-B｜「可观测」免费，「状态依赖」只付一次配对跑
- **主张**：「外部只读输出流即可复读」的代价 = **0 在线内存 / 0 乘加**（只写日志，2000 拍正文日志 <1MB [推算]）；「文本↔状态」的置换/清经历检验只需同一段**跑两遍**（主臂 + 置换臂），代价 = 该段墙钟 ×2，**不需要**在线互信息估计。
- **证据**：P1 判据形态（简报 §0 P1）；日志量：2000 拍 ×（1 文本单位 + 32B 状态哈希）≈ 0.4MB。
- **反证**：若判据要求**在线** MI（每拍 O(V) 词频更新 + 双趟状态快照对比），则需 +35.22MB/拍 scratch [实测] ⇒ 120 拍峰值 167.90 → **约 203MB**，320 线仍成立但余量从 47% 降到 36%。**必须失败对照臂**：冻结状态臂——文本必须**逐位不变**（若变了 ⇒ 正文还在吃别的随机源，判据漏项）。
- **算力代价**：置换臂 +120 拍 × 载体（两区室核 1.553ms ⇒ **0.19s**；千层 D=64 ⇒ 1.96s）[推算]。

## 2. T2 · 旁路由并行：三线预算与「互斥」的硬判据

### 四件套 T2-A｜100ms 时基下：96.0ms 载体**必然**破线；其余载体取决于未测的旁路由开销
- **主张**：把「正文 A + 旁路由 B + 观测 C + 调度 D」当固定开销，则 **100ms 帧剩余给内心迭代 = 100 − 链 − (A+B+C+D)**。B、C **未测** ⇒ 本队不假装知道，改为给**翻转点**与**两条硬结论**：
  - **硬结论①（不依赖任何未测值）**：**96.0ms 载体**在 100ms 帧下，即使 A+B+C+D 只取 18ms（极乐观），剩余也 **<0**（100−96−18 = −14）⇒ **三线并行不可能**；须 ≥**114ms** 时基（极乐观）/ ≥**169ms**（B+C=45ms）/ 或独占。
  - **硬结论②**：**全链 D=1024（p90 49.07）** 在乐观开销 39ms 下，100ms 帧剩余 **11.93ms** ⇒ **连 1 步千层 D=64（16.3ms）都放不下**；**200ms 帧**剩余 **111.93ms** ⇒ K≤6。
- **证据**：墙钟 [实测]：全链 D=1024 median **30.44** / min 23.28 / p90 **49.07**；千层 D=256 median **71.17** / p90 **123.36**；千层 D=64 **15.6–16.3/步**；两区室核 **1.553ms/拍**；「96.0ms 载体」「0.15–0.285ms」为 meeting52 G4/G7 锚点。**注意 0.285 vs 1.553 差 5.4×** ⇒ 二者口径不同（前者疑为核本体、后者为含宿主的 `前向_双区室` 3 令牌）；本队 K_max 一律取 **1.553ms** 保守值，并把该口径差列入未测（U7）。
- **反证**：若独占实测 A+B+C+D ≤ 18ms **且** 96.0ms 载体实测 ≤ 82ms（G7 高估），则硬结论①推翻。**必须失败对照臂**：**串行臂**（先跑完内心再跑旁路由）在同一载体上预期 ≥169ms；若串行臂也报 ≤100ms，说明计时漏了 flush/注入 ⇒ 整表判 **VOID⇒FAIL**。
- **算力代价**：判定本身 120 拍 × 4 载体 ≈ **12s 独占** [推算]；不占内存。
- **两条可行组合**（[设计值/推算]，均需独占）：①**100ms + 两区室核(1.553)**：K≤38（配额 59.45ms）；②**200ms + 全链(p90 49.07) + 千层 D=64**：K≤6（配额 111.93ms）。**p90 立预算的代价就是「宿主链 100ms 只能 K=0」**——这是本队对 T3 的直接资源判决。

### 四件套 T2-B｜「同拍」必须与「真机原子耗时」一起判，否则是纸面并行
- **主张**：真机档 `moveTo(duration=0.1)` = **100ms/原子**（`真机探头.py:317`）⇒ **单个键鼠原子就吃满一整帧**；此时"三线同拍"只在"每拍各有推进"的重定义下成立，若坚持"帧内三线各完成一次"，真机档**结构性不可能**。
- **证据**：`真机探头.py:317,331,329`（duration 0.1 / 键入 0.02s/字）[实测·源码]；风险清单员 R6。
- **反证**：若真机实测单原子 median ≤20ms（duration 未被真实使用），R6 解除。**必须失败对照臂**：沙箱记账档（0 次 pyautogui 调用）必须显示 `动作阻塞 ≈ 0`——若沙箱档也报 100ms/原子，说明该字段读的是设计模型而非实测。
- **算力代价**：真机单会话 ≥3min [推算]，需所有者在场；沙箱档 0 成本。

## 3. T3 · 内心思考：预算内最大步数（按载体、p90 口径）

**算法（写死，可用手算复核）**：内心配额 = 帧长 − 该载体主链墙钟 − 40ms（正文 12 + 调度/守卫/写盘 6 + 旁路由/观测 22，乐观值，**未测**）；K_max = ⌊配额 / 单步 m⌋，同一载体的单步 m = 其主链墙钟（保守：思考步与主链一拍同价）。

| 载体（主链墙钟 = 单步 m） | 100ms 帧：配额 → K_max | 200ms 帧：配额 → K_max | 判定 |
|---|---|---|---|
| 两区室核 **1.553ms** [实测] | 59.45 → **≤38** | 159.45 → **≤102** | ✅ 唯一两档都够做「难度→步数」（3 档可比） |
| 千层 D=64 **16.3ms** [实测] | 44.7 → **≤2** | 144.7 → **≤8** | 100ms 仅 2 步（勉强 3 档不可比） |
| 全链 D=1024 **p90 49.07** [实测] | **11.93 → 0** | 111.93 → **≤6** | 100ms 放不下 |
| 千层 D=256 **median 71.17 / p90 123.36** [实测] | **−10.17 → 0** | median 89.83 → **≤1**；p90 37.64 → **0** | ❌ 两档都撑不起步数调度 |
| 「96.0ms 载体」[实测 G7] | **−36 → 0**（缺口 36ms） | **≤3**（独占）；并发（≥200ms 时基下实际 200–384）⇒ **0** | ❌ 独占也只能勉强 |

**四件套 T3-A**
- **主张**：**只有两区室核（1.553ms/步）在 100ms 与 200ms 两档都能做「难度→步数」实验**；千层 D=64 只能在 200ms 档做；千层 D=256 与「96.0ms 载体」**两档都不行**。
- **证据**：上表 + 锚点来源（R3 三分位、G7、工程路径员探针）。
- **反证**：若某载体实测单步比锚点快 2×，K_max 上修——但**K 上修不得替代因果臂**。**必须失败对照臂**：同载体 K=1 单次投影 vs K=K_max；若两者决策统计量 TVD < 0.10，则「步数有因果」当场被推翻（这是按 `裁决:45,59,74` C8/F2 与丙1「迭代 1=3 逐位同」的**预期结果**，不是意外）。
- **算力代价**：每拍 ③ = K × m；100ms 档两区室核 K≤38 ⇒ ≤59.0ms；200ms 档 K≤102 ⇒ ≤158.4ms。

**四件套 T3-B｜结构提醒（资源方必须代别队先说）**
- **主张**：**K_max 是"预算内还能算几步"的上限，不是能力判据**。资源宽裕**不能**被用来论证"思考深"。
- **证据**：[实测] 千层 6 档−1 档迁移差 **−0.004**（`裁决:130` 甲2）；丙1 迭代 1 步与 3 步**逐点同**（`裁决:163`）；C8/F2：「8 算子仅 `读` 带跨维混合 ⇒ 逐元素 + 固定驱动 ⇒ 唯一不动点」⇒「迭代次数＝思考深度」在算子层被堵死（`裁决:45,59,74`）。
- **反证**：若某机制在 K 扫描下决策统计量随 K 单调改变（TV 随 K 上升且 CI 不含 0），则该机制**局部**破除了结构定理——但必须同时过 C1 自检（含 `读` 行）。**必须失败对照**：固定步数臂（步数≡3）与"按难度调度"臂必须可分。
- **算力代价**：TVD 估计需 K 档 × 2 趟 × 60 拍；K≤6 ⇒ 约 **12 跑 ≈ 24s** [推算]。

## 4. T4 · 多脑协作：N 脑账（本队最可能改写别队方案的一节）

### 四件套 T4-A｜「N 脑」的成本不是「引擎 24MB × N」，是「一整脑 × N」
- **主张**：按**每脑真实增量**计，则 `WS(N) ≈ 28 + N×227` MB、`commit(N) ≈ 16.8 + N×273` MB（全链 D=1024，threads=1，2000 拍）：

  | 载体 | N=1 | N=3 | N=5 | 判定 |
  |---|---|---|---|---|
  | **全链 D=1024** | WS **256.59** / commit **306.11** [实测] | WS **709** / commit **836** [推算] | WS **1163** / commit **1382** [推算] | **N=1 贴线（commit 95.7%）；N≥2 一律破 320 与/或 1GB** |
  | 全链 D=1024 · **默认线程** | commit **1252.2** [实测] | commit **1326** | commit **1872**；**多进程 N=5 = 5×1252 = 6261MB > 并发期 free 4.26GiB ⇒ 必 OOM** | 破 1GB 1.2–1.8× |
  | **千层 D=256** | WS **87.96** / commit **106.54** [实测] | WS **204** / commit **286** [推算] | WS **322** / commit **465** [推算] | **N≤3 可行；N=5 破 320** |
  | **D=64（H 项载体）** | RSS **32.5–32.8** / commit **18.9**（每进程）[实测] | 多进程 RSS **97.5** / commit **56.7** | 多进程 RSS **162.5** / commit **94.5** [推算] | **N=5 唯一算得起的载体** |

- **证据**：R3 前后基线差分（起拍前 RSS 27.96 / commit 16.77；2000 拍 peak 256.59 / 306.11）+ 千层 D=256 同表 + H 项 `H_轴A_C_pass1/2.json:419`。
- **反证**：①若实测 N=3 单进程 WS ≤250MB，说明实例间共享了缓冲（"3 个脑"其实是 1 个脑的 3 个视图）⇒ 加性公式高估 **且** T4 的"独立性"本身可疑，须由通信臂证明；②切 CUDA：上下文 **142MiB/进程加性**（1/2/3 → 278/420/562 [实测]）⇒ **384MiB 只容 1 进程**，N≥2 的 CUDA 臂**直接否**（不是超线，是不可用）。
- **算力代价**：N=3 @千层 D=256（71.17ms/拍）×400 拍 ×2 趟 ≈ **171s** [推算]；N=3 @D=64（16.3ms）×400×2 ≈ **39s**。
- **必须失败对照**：**等算力单脑臂**（1 脑 × N 倍算力/拍数）——若它不掉分 ⇒ 增益来自算力而非通信 ⇒ **协作判 FAIL**。

### 四件套 T4-B｜T4 判据必须声明载体，否则「算不起」会被误读成「方案不合格」
- **主张**：同一套 T4 判据在三载体上的价格差 **≥6×**（39s / 171s / 多进程全链约 3×171s）。**任何 T4 方案若只写"N=3"不写载体与 D，其资源承诺不可兑现、结论不可复现** ⇒ 按 VOID 处理。
- **证据**：上表 + §3 载体表。
- **反证**：若主控冻结单一载体为「全链 D=1024」，则 T4 的 N≥2 一律**算不起**（破线），T4 只能判 N=1 与"模拟多脑（单实例多视图）"——**后者不是协作，必须标 INVALID**。**必须失败对照**：N=3 臂若在 320 线内"顺利过"，先查是否共享了缓冲（见 T4-A 反证①）。
- **算力代价**：见上；两趟 ×2.0 单列。

## 5. T5 · 整机：常驻闭环、资源账、算不起清单

### 四件套 T5-A｜整机常驻「窄幅可行」，且只有一条组合
- **主张**：可执行的整机组合 = **200ms 时基 + 全链 D=1024（p90 49.07）+ 千层 D=64 内心 K≤6（≤97.8ms）+ 正文 ≤12 + 旁路由/观测/调度 ≤39（未测）+ 余量**：**p90 合计 ≤197.9ms / 200ms，余量 ≈2ms**；内存（2000 拍）**commit 306.11MB = 320 线的 95.7%**（余量已被迹增长吃掉）。⇒ **成立但零余量：2000 拍就是天花板**（外推 **~2294 拍**触 320，斜率 0.04709MB/拍 [实测]）。
- **证据**：R3 全链 2000 拍 peak 256.59 / commit 306.11、斜率与外推；千层 D=64 16.3ms；其余 [设计值]。
- **反证**：①B（旁路由+观测）实测 >39ms ⇒ 破 200ms；②K 必须 ≥7 ⇒ 破；③迹增长未封顶 ⇒ 2000 拍后必破 320（**"常驻恒定"不成立**，根因 `内核_自我回路.py:85,138` 每拍 append 无上限，2000 拍 2245 条 [实测]）。**必须失败对照臂**：**2×2 联合消融（拆正文 × 拆回流）**——若交互项 |I| >0.10，则"分项 PASS 拼整机 PASS"**直接判 INVALID**（议题 T5 红队要求）。
- **算力代价**：整机 2000 拍 ≈ **81.02s**（全链，R3）+ 迹增长；两趟 ×2。

### 四件套 T5-B｜最小可判子集：10 臂 / 两趟 135.4s / 预算 300s

### 6.2 分项归因（补「76% 未归因」——那 76–82% 是 torch，不是全链内部）
- **torch+全链 commit 1077.88** = torch 常驻 **881.83（81.8%）** + 全链构建增量 **129.02（12.0%）** + 预热/运行/碎片 **67.03（6.2%）** [实测 R3 §2.1]。

### 6.3 并发纪律
- 并发期**只记读数、不判效率**（G6/G7 先例：同一载体 96.0 → 并发 200–384ms，**2.1–4.0×**）；效率类数字须 `窗口=独占 ∧ 重复≥3`，否则 **INVALID**。
